# Mail

Mail access goes through the Speedwave MCP Hub. Claude does not see `mail__*` tools directly: use `search_tools` to discover them and `execute_code` with the injected `os` global to invoke. Tools are called as `await os.<methodName>({ … })`.

macOS Mail.app unifies all accounts configured in **System Settings, Internet Accounts**: iCloud, Gmail, Exchange, IMAP, and others are all accessible through the same `os.listMailboxes` / `os.listEmails` surface. No per-account credentials are needed; the mcp-os worker uses Automation permission (TCC), pre-validated on first enable.

## Workflow

1. `search_tools({ query: "mail", detail_level: "names_only", service: "os" })`: discover what is available.
2. `search_tools({ query: "os__<toolName>", detail_level: "full_schema", service: "os" })`: get the exact parameter schema.
3. `execute_code`: call the tool using the parameter names from the schema.

Always run steps 1–2 before guessing a tool name or parameter. The live schema is the source of truth.

## Pitfalls

- **`os.*`, not `mail.*`.** All four OS sub-services (mail, calendar, reminders, notes) share the same `os` global. There is no `mail` global.
- **A mailbox is a case-sensitive path inside an account** (e.g. `Inbox/Clients` for a nested mailbox). Call `os.listMailboxes` first and pass its `name` as `mailbox` and its `account` as `account`; do not guess folder paths. Local mailboxes are listed under the account `On My Mac`. `os.listEmails` and `os.searchEmails` always take a `mailbox`; without `account` a name several accounts have (e.g. `INBOX`) is refused as ambiguous.
- **Listing returns metadata only, newest first.** `os.listEmails` returns subject, sender, date (ISO 8601 with offset), read status, mailbox and account, plus `total`; page with `offset`/`limit` (more pages while `offset + emails.length < total`) and pass `unread_only: true` for unread mail. Retrieve the body with a separate `os.getEmail({ id })` call. Be selective; fetching many bodies in a loop can be slow and token-heavy.
- **An email's `id` is an opaque mail id.** Pass the `id` from `os.listEmails` or `os.searchEmails` unchanged to `os.getEmail`, `os.replyToEmail`, `os.forwardEmail` and `os.redirectEmail`; it already names the account and mailbox, so it works for any mailbox. Never build or edit one, and never pass a raw Message-ID.
- **Sending goes through a preview and the user's yes.** Call `os.sendEmail({ to, subject, body, cc?, bcc? })` or `os.replyToEmail({ id, body, reply_all? })` first without `confirm_send`: nothing is sent, and the answer has `status: "confirmation_required"` with `to`, `cc` (and `bcc` for a new email), `subject` and `body`, the full text that would go out. Show all of it to the user, ask "send this?", and only after a yes call again with the same arguments and `confirm_send: true`; a no means do not call again. Never set `confirm_send: true` on the first call. Mail is plain text only: line breaks are kept, HTML would arrive as literal tags, and no file can be attached.
- **A reply works on a mail in any mailbox and quotes it.** Mail picks the recipients and the `Re:` subject (`reply_all: true` adds every recipient of the original); your `body` goes above a blank line, an `On <date>, <sender> wrote:` line and the original quoted with `>`, so pass only the new text.
- **Forwarding and redirecting go through the same preview and yes.** `os.forwardEmail({ id, to, cc?, comment? })` sends Mail's own forward (its `Fwd:` subject, the email quoted, all its attachments) with your optional plain-text `comment` above it; `os.redirectEmail({ id, to, cc? })` sends the email unchanged, attachments included, so the recipients see it from its original sender, and takes no comment. Use forward when the user wants to add a note or appear as the sender, redirect when the email should arrive as if sent to them directly. Both answer first without `confirm_send` with `status: "confirmation_required"`, `to`, `cc`, `subject`, `comment` (forward), `original` (sender, subject, date, mailbox) and `attachments` (names that go along): show it, ask "send this?", and only after a yes call again with the same arguments and `confirm_send: true`.
- **Deleting goes through a preview and the user's yes.** `os.deleteEmails({ ids })` moves 1 to 25 emails (mail ids from `os.listEmails`/`os.searchEmails`) to the Trash of their own account; nothing deletes permanently. Without `confirm_delete: true` it changes nothing and returns `status: "confirmation_required"` with each email's sender, subject, date, mailbox and account: show that list, ask the user "are you sure?", and only after a yes call again with the same `ids` and `confirm_delete: true`. A no means do not call again. For more than 25 emails, split them into batches of at most 25 and confirm each batch separately (`MAIL_BATCH_TOO_LARGE` otherwise). The confirmed call reports every email: `status` is `completed`, `partial` or `failed`, with `succeeded`/`failed` counts and per email `ok` or its `error`; tell the user which ones were not moved and why, never "all done" on a partial result.
- **Organizing needs no confirmation; spam does.** `os.markEmailsRead({ ids, read })`, `os.flagEmails({ ids, flag })` (`red`, `orange`, `yellow`, `green`, `blue`, `purple`, `gray`, or `none` to take the flag off), `os.moveEmails({ ids, mailbox, account })`, `os.copyEmails({ ids, mailbox, account })` and `os.archiveEmails({ ids })` are reversible and act at once on 1 to 25 mail ids. The target of a move or copy is a mailbox together with its account, exactly as `os.listMailboxes` returns them; create a missing one with `os.createMailbox({ name, account })` (`Clients/Acme` nests Acme inside Clients; an existing name is refused with `MAIL_MAILBOX_EXISTS`, so just use it). A moved or archived email gets a new mail id: list the target mailbox before acting on it again. Archiving moves each email to the Archive mailbox of its own account (All Mail on Gmail); an account without one reports `MAIL_ARCHIVE_NOT_FOUND` for that email and leaves it in place, so ask the user where it should go and use `os.moveEmails`. `os.markEmailsSpam({ ids })` trains Mail's junk filter and moves the emails to the Junk mailbox, so it goes through the same preview and "are you sure?" as deleting, with `confirm_spam: true`. Every one of these reports per email like `os.deleteEmails` does; report failures by email.
- **Sending is irreversible.** Once `os.sendEmail`, `os.replyToEmail`, `os.forwardEmail` or `os.redirectEmail` returns `status: "sent"` (with what was sent), the message is in the MTA queue. `MAIL_SEND_FAILED` means Mail did not send it: tell the user to check the Outbox and do not retry without asking. There is no undo. Drafts (compose without send) are not exposed as a tool; if the user only wants to draft, explain this limitation.
- **`os.getEmail` returns the whole email but not attachment content.** It gives sender, `to`, `cc`, the ISO 8601 date, the plain-text body, the mailbox and account, and `attachments` (each with `index`, `name`, `size` in bytes when known and `mime_type`); the files themselves are not returned. To diagnose a suspicious email (spoofed sender, phishing, delivery path) pass `include_headers: true` for every header or `include_source: true` for the raw source; either is cut at 100000 characters, and `headers_truncated`/`source_truncated` say when it was.
- **Search scope.** `os.searchEmails` searches the one mailbox named by `mailbox`. For searches across mailboxes, list target mailboxes with `os.listMailboxes` first and call `os.searchEmails({ query, mailbox, account })` for each.
- **Search matches subject and sender; the body only on request.** `os.searchEmails({ query, mailbox, account })` is fast even in a large mailbox and returns the newest matches first with `total`; narrow it with `sender`, `since`/`before` (ISO 8601, e.g. `2026-10-01`) and `unread_only`, and page with `offset`/`limit`. Set `search_body: true` only when the user asks to search the email text: Mail then reads every body, which can take minutes, so tell the user it will take a while.
- **A failed call says what to fix.** The error code names the cause: `MAIL_TIMEOUT` (Mail.app did not answer in time: retry once with a specific `mailbox` or a smaller `limit`, and check the Sent mailbox before retrying a send or reply), `MAIL_AUTOMATION_DENIED` (ask the user to allow Speedwave to control Mail in System Settings, Privacy & Security, Automation), `MAIL_MAILBOX_NOT_FOUND`, `MAIL_ACCOUNT_NOT_FOUND` and `MAIL_MAILBOX_AMBIGUOUS` (take the `name` and `account` from `os.listMailboxes`), `MAIL_INVALID_ID` (pass an `id` from `os.listEmails` or `os.searchEmails` unchanged), `MAIL_NOT_FOUND` (the email was moved or deleted since its id was listed: list or search its mailbox again), `MAIL_MAILBOX_CHANGED` (mail arrived or moved during the read: retry once), `MAIL_MAILBOX_EXISTS` (`os.createMailbox` found the mailbox already there: use it). Follow the error's instruction instead of retrying the same call.
- **Rules are read-only.** `os.listMailRules()` returns each rule's name, `enabled`, `match_all`, `conditions` and `actions` (move/copy target, forward or redirect address, reply text): use it to explain why mail lands where it does. No tool creates, changes or deletes a rule, by design (a malicious mail must not be able to set up permanent forwarding); if the user wants a rule changed, tell them to do it in Mail > Settings > Rules.
- **`os.checkMail()` only starts a fetch.** It asks Mail.app to fetch new mail for every account, or for one with `{ account }` (the `account` from `os.listMailboxes`), and returns at once with `status: "started"`; list or search again after a few seconds to see what arrived.
- **Apple Mail is the only client.** The mail tools drive Apple Mail and take no `client` parameter; passing one is rejected. Microsoft Outlook is not supported (New Outlook has no AppleScript, Legacy Outlook no longer connects to Exchange Online): when `os.detectMailClients` lists it with `supported: false`, relay its `instructions` to the user, which explain how to add the account to Apple Mail.

## When NOT to use

- Web-based mail accessed through a browser (no native Mail.app account configured).
- IMAP/SMTP server configuration questions: those belong in System Settings.
- Generic email-writing or marketing-copy advice: no tool call needed.
