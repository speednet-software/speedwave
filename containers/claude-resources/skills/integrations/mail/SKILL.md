# Mail

Mail access goes through the Speedwave MCP Hub. Claude does not see `mail__*` tools directly: use `search_tools` to discover them and `execute_code` with the injected `os` global to invoke. Tools are called as `await os.<methodName>({ … })`.

macOS Mail.app unifies all accounts configured in **System Settings, Internet Accounts**: iCloud, Gmail, Exchange, IMAP, and others are all accessible through the same `os.listMailboxes` / `os.listEmails` surface. No per-account credentials are needed; the mcp-os worker uses Automation permission (TCC), pre-validated on first enable.

## Workflow

1. `search_tools({ query: "mail", detail_level: "names_only", service: "os" })`: discover what is available.
2. `search_tools({ query: "os__<toolName>", detail_level: "full_schema", service: "os" })`: get the exact parameter schema.
3. `execute_code`: call the tool using the parameter names from the schema.

Always run steps 1–2 before guessing a tool name or parameter. The live schema is the source of truth.

## Pitfalls

- **`os.*`, not `mail.*`.** All four OS sub-services (mail, calendar, reminders, notes) share the same `os` global. There is no `mail` global.
- **A mailbox is a case-sensitive path inside an account** (e.g. `Inbox/Clients` for a nested mailbox). Call `os.listMailboxes` first and pass its `name` as `mailbox` and its `account` as `account`; do not guess folder paths. Local mailboxes are listed under the account `On My Mac`. `os.listEmails` always takes a `mailbox`, and so does `os.searchEmails` when it searches one mailbox; without `account` a name several accounts have (e.g. `INBOX`) is refused as ambiguous.
- **Listing returns metadata only, newest first.** `os.listEmails` returns subject, sender, date (ISO 8601 with offset), read status, `flag` (the flag color, or `none` when the email is not flagged), `attachment_count`, mailbox and account, plus `total`; page with `offset`/`limit` (more pages while `offset + emails.length < total`), pass `unread_only: true` for unread mail and `flagged_only: true` for flagged mail. `attachment_count` shows which emails have attachments without opening them, but Mail also counts images embedded in the text, so a nonzero count is not always a file: `os.getEmail({ id })` gives the exact list. Retrieve the body with a separate `os.getEmail({ id })` call. Be selective; fetching many bodies in a loop can be slow and token-heavy.
- **Counting unread mail takes one call.** Every mailbox from `os.listMailboxes` carries `unread_count` next to `message_count`: add up the `unread_count` of the mailboxes the user means (for "how many unread do I have", the inboxes of every account). List the unread emails themselves with `os.listEmails({ mailbox, account, unread_only: true })`.
- **Counting flagged mail takes one call.** `os.searchEmails({ flagged_only: true, limit: 1 })` without `mailbox` searches every mailbox but Trash and Junk, and its `total` is the number of flagged emails; add `account` to count one account. For the count of one mailbox pass its `mailbox` and `account`. `unread_only: true` counts unread mail the same way across mailboxes. The rows say which color each email carries.
- **An email's `id` is an opaque mail id.** Pass the `id` from `os.listEmails` or `os.searchEmails` unchanged to `os.getEmail`, `os.replyToEmail`, `os.forwardEmail` and `os.redirectEmail`; it already names the account and mailbox, so it works for any mailbox. Never build or edit one, and never pass a raw Message-ID.
- **Sending goes through a preview and the user's yes.** Call `os.sendEmail({ to, subject, body, cc?, bcc?, account? })` or `os.replyToEmail({ id, body, reply_all?, cc?, bcc? })` first without `confirm_send`: nothing is sent, and the answer has `status: "confirmation_required"` with `to`, `cc`, `bcc` (and `from` for a new email), `subject` and `body`, the full text that would go out. `from` is the sender Mail will use, read from Mail: the `account` you pass (an account name from `os.listMailboxes`), or without one Mail's primary address (else the first turned-on account), which may differ from the "Send new messages from" choice in Mail's settings. Always name the `from` to the user; if it is not the address they want, call again with their `account`. A reply goes to the recipients Mail chooses; its `cc` and `bcc` add people (for "reply all and add Ewa in CC"), and the preview lists every address that will get it. Show all of it to the user, `from` included, so they see which address the email leaves from, ask "send this?", and only after a yes call again with the same arguments and `confirm_send: true`; a no means do not call again. Never set `confirm_send: true` on the first call. Mail is plain text only: line breaks are kept, HTML would arrive as literal tags, and no file can be attached. To sign with a specific Mail signature, pass its name from `os.listMailSignatures()` as `signature` (to `os.sendEmail`, `os.replyToEmail` or `os.saveDraft`); without it no signature is added, not even the account's default, so the previewed `body` is all the text that goes out. With one, the preview names the `signature` Mail adds below the `body`: tell the user which signature it is. An unknown name is `MAIL_SIGNATURE_NOT_FOUND`. Apple Mail shows text a script sets as a quote: the recipient of `os.sendEmail` or `os.replyToEmail`, and a draft from `os.saveDraft`, gets the `body` with `>` before each line in plain text and as a cited block in HTML. This is a Mail bug no tool avoids, so say so when you ask "send this?"; a forward or a redirect is not affected.
- **A reply works on a mail in any mailbox and quotes it.** Mail picks the recipients and the `Re:` subject (`reply_all: true` adds every recipient of the original); your `body` goes above a blank line, an `On <date>, <sender> wrote:` line and the original quoted with `>`, so pass only the new text.
- **Forwarding and redirecting go through the same preview and yes.** `os.forwardEmail({ id, to, cc? })` sends Mail's own forward (its `Fwd:` subject, the email quoted, all its attachments); `os.redirectEmail({ id, to, cc? })` sends the email unchanged, attachments included, so the recipients see it from its original sender. Neither takes a comment: Mail drops the quote and the attachments of a forward whose text is changed, so if the user wants a note with it, send the note as a separate email. Use forward when the user should appear as the sender, redirect when the email should arrive as if sent to them directly. Both answer first without `confirm_send` with `status: "confirmation_required"`, `to`, `cc`, `subject`, `original` (sender, subject, date, mailbox) and `attachments` (names that go along): show it, ask "send this?", and only after a yes call again with the same arguments and `confirm_send: true`.
- **Deleting goes through a preview and the user's yes.** `os.deleteEmails({ ids })` moves 1 to 25 emails (mail ids from `os.listEmails`/`os.searchEmails`) to the Trash of their own account; nothing deletes permanently. Without `confirm_delete: true` it changes nothing and returns `status: "confirmation_required"` with each email's sender, subject, date, mailbox and account: show that list, ask the user "are you sure?", and only after a yes call again with the same `ids` and `confirm_delete: true`. A no means do not call again. For more than 25 emails, split them into batches of at most 25 and confirm each batch separately (`MAIL_BATCH_TOO_LARGE` otherwise). The confirmed call reports every email: `status` is `completed`, `partial` or `failed`, with `succeeded`/`failed` counts and per email `ok` or its `error`; tell the user which ones were not moved and why, never "all done" on a partial result. An email reported `MAIL_NOT_ATTEMPTED` was left unchanged because the batch ran out of time; call again with those ids only.
- **Organizing needs no confirmation; spam does.** `os.markEmailsRead({ ids, read })`, `os.flagEmails({ ids, flag })` (`red`, `orange`, `yellow`, `green`, `blue`, `purple`, `gray`, or `none` to take the flag off), `os.moveEmails({ ids, mailbox, account })`, `os.copyEmails({ ids, mailbox, account })` and `os.archiveEmails({ ids })` are reversible and act at once on 1 to 25 mail ids. The target of a move or copy is a mailbox together with its account, exactly as `os.listMailboxes` returns them; create a missing one with `os.createMailbox({ name, account })` (`Clients/Acme` nests Acme inside Clients; an existing name is refused with `MAIL_MAILBOX_EXISTS`, so just use it). Rename one with `os.renameMailbox({ mailbox, account, new_name })`: `new_name` is one name without `/`, the mailbox stays in its parent, and renaming it back undoes it. Mail's own mailboxes (Inbox, Drafts, Sent, Junk, Trash, Outbox and the archive) keep their names and are refused with `MAIL_SPECIAL_MAILBOX`; a name the parent already has is refused with `MAIL_MAILBOX_EXISTS`, so ask the user for another one. A move or copy into the account's Trash or Junk mailbox is refused (`MAIL_TARGET_IS_TRASH`, `MAIL_TARGET_IS_JUNK`): deleting goes only through `os.deleteEmails` and reporting spam only through `os.markEmailsSpam`, each with its preview and the user's yes. A moved or archived email gets a new mail id: list the target mailbox before acting on it again. Archiving moves each email to the Archive mailbox of its own account (All Mail on Gmail); an account without one reports `MAIL_ARCHIVE_NOT_FOUND` for that email and leaves it in place, so ask the user where it should go and use `os.moveEmails`. `os.markEmailsSpam({ ids })` trains Mail's junk filter and moves the emails to the Junk mailbox, so it goes through the same preview and "are you sure?" as deleting, with `confirm_spam: true`. Its reverse, `os.markEmailsNotSpam({ ids })`, needs no confirmation: it takes the junk mark off each email, which also trains the filter, and moves an email that sits in the Junk mailbox of its account back to that account's Inbox. Each email in its report carries `moved`: false means it stayed where it was, because it was not in Junk or because it is in On My Mac, which has no Inbox. Every one of these reports per email like `os.deleteEmails` does; report failures by email.
- **Sending is irreversible.** Once `os.sendEmail`, `os.replyToEmail`, `os.forwardEmail` or `os.redirectEmail` returns `status: "sent"` (with what was sent), the message is in the MTA queue. `MAIL_SEND_FAILED` means Mail did not send it: tell the user to check the Outbox and do not retry without asking. There is no undo.
- **A draft is saved, never sent, and needs no confirmation.** When the user wants to finish an email themselves, call `os.saveDraft({ subject, body?, to?, cc?, bcc?, account?, signature? })`: it lands in the Drafts mailbox of `account` (the `account` from `os.listMailboxes`; Mail's primary address when omitted) and returns `status: "saved"` with what was saved, `from` included. Tell the user it is waiting in Drafts in Mail.app under that `from`; nothing went out.
- **`os.getEmail` returns the whole email but not attachment content.** It gives the subject, sender, `read`, `to`, `cc`, the ISO 8601 date, `flag`, the plain-text body, the mailbox and account, and `attachments` (each with `index`, `name`, `size` in bytes when known and `mime_type`); the files themselves are not returned. To diagnose a suspicious email (spoofed sender, phishing, delivery path) pass `include_headers: true` for every header or `include_source: true` for the raw source; either is cut at 100000 characters, and `headers_truncated`/`source_truncated` say when it was.
- **Search scope.** When you do not know where an email lies, call `os.searchEmails` without `mailbox`: it searches every mailbox of `account`, or of every account and On My Mac when `account` is left out too, and returns one page sorted newest first, with `total` counted over all of them. Each row names its own `mailbox` and `account`. The Trash and Junk mailboxes are left out of such a search; to look there, name the mailbox as `mailbox` (with its `account`). With `mailbox` it searches only that one mailbox. A body search (`search_body: true`) always needs one `mailbox`.
- **Search combines filters; the body only on request.** `os.searchEmails({ mailbox, account, ... })` is fast even in a large mailbox and returns the newest emails every given filter matches, with `total`. The filters are `query` (the subject or the sender contains it), `sender`, `recipient` (a whole email address in To or Cc, e.g. `anna@example.com`), `since`/`before` (ISO 8601, e.g. `2026-10-01`), `unread_only` and `flagged_only`; give at least one, and use `os.listEmails` to list a whole mailbox. A query is optional: "mail from last week" is `since` and `before` alone, and "what did I send Anna" is `recipient` on the Sent mailbox. `recipient` matches only a whole address, so first find Anna's address: `os.searchEmails({ sender: "Anna" })` or `os.searchEmails({ query: "Anna" })` shows it in the `sender` of her emails, and `os.getEmail({ id })` of a known email lists its `to` and `cc`. Page with `offset`/`limit`. Set `search_body: true` (it needs a `query`) only when the user asks to search the email text: Mail then reads every body, which can take minutes, so tell the user it will take a while.
- **A failed call says what to fix.** The error code names the cause: `MAIL_TIMEOUT` (Mail.app did not answer in time; `limit` does not make Mail faster: for a list or search, narrow it with `unread_only`, `flagged_only`, `since`, `before` or `sender`, or search one `mailbox`; for anything that changes mail, never retry: a batch may have changed some emails already, so list their mailboxes again and tell the user before acting on the rest, and never repeat `os.copyEmails`; a send, reply, forward or redirect may have gone out, so search the Sent mailbox and tell the user; a draft may be saved, so look in Drafts; a created or renamed mailbox shows in `os.listMailboxes`), `MAIL_AUTOMATION_DENIED` (ask the user to allow Speedwave to control Mail in System Settings, Privacy & Security, Automation), `MAIL_MAILBOX_NOT_FOUND`, `MAIL_ACCOUNT_NOT_FOUND` and `MAIL_MAILBOX_AMBIGUOUS` (take the `name` and `account` from `os.listMailboxes`), `MAIL_ACCOUNT_AMBIGUOUS` (several Mail accounts share the account name you passed, so nothing was done: ask the user to give one of them another description in Mail > Settings > Accounts, and never guess which one they meant), `MAIL_INVALID_ID` (pass an `id` from `os.listEmails` or `os.searchEmails` unchanged), `MAIL_NOT_FOUND` (the email was moved or deleted since its id was listed: list or search its mailbox again), `MAIL_MAILBOX_CHANGED` (mail arrived or moved during the read: retry once), `MAIL_MAILBOX_EXISTS` (`os.createMailbox` found the mailbox already there: use it; for `os.renameMailbox` ask the user for another name), `MAIL_SPECIAL_MAILBOX` (`os.renameMailbox` does not rename Mail's own mailboxes), `MAIL_SIGNATURE_NOT_FOUND` (take the name from `os.listMailSignatures`), `MAIL_ACCOUNT_DISABLED` (the account is turned off in Mail: ask the user whether to turn it on in Mail > Settings > Accounts or to send from another account, and never retry a send without asking; for another account call again with it, or without `account`, and show the user the new `from`), `MAIL_NO_SENDER` (Mail has no turned-on account with an address: ask the user to add or turn one on). Follow the error's instruction instead of retrying the same call.
- **Rules are read-only.** `os.listMailRules()` returns each rule's name, `enabled`, `match_all`, `conditions` and `actions` (move/copy target, forward or redirect address, reply text): use it to explain why mail lands where it does. No tool creates, changes or deletes a rule, by design (a malicious mail must not be able to set up permanent forwarding); if the user wants a rule changed, tell them to do it in Mail > Settings > Rules.
- **`os.checkMail()` only starts a fetch.** It asks Mail.app to fetch new mail for every account, or for one with `{ account }` (the `account` from `os.listMailboxes`), and returns at once with `status: "started"`; list or search again after a few seconds to see what arrived.
- **Apple Mail is the only client.** The mail tools drive Apple Mail and take no `client` parameter; passing one is rejected. Microsoft Outlook is not supported (New Outlook has no AppleScript, Legacy Outlook no longer connects to Exchange Online): when `os.detectMailClients` lists it with `supported: false`, relay its `instructions` to the user, which explain how to add the account to Apple Mail.

## When NOT to use

- Web-based mail accessed through a browser (no native Mail.app account configured).
- IMAP/SMTP server configuration questions: those belong in System Settings.
- Generic email-writing or marketing-copy advice: no tool call needed.
