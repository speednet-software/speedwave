# Desktop UI Rules (Angular + Tauri)

- **Zoneless + OnPush: service state read by a template MUST be a signal.** A template reading a plain service property renders stale — nothing schedules change detection. New service fields consumed by templates are signals (or computed) from day one.
- **Rust ↔ TS model mirrors are silent-failure surfaces:** Tauri command return types and their `models/*.ts` counterparts must match exactly — the JSON deserializer silently drops unknown/mismatched fields. Update both sides in the same commit; for a new mirrored constant/union add an `include_str!` cross-read test on the Rust side (grep `_matches_ts` for the pattern).
- **State-tree rendering:** a new `MessageBlock` variant lands in Rust first, then `models/state-tree.ts::MessageBlockState`, then a renderer arm in `chat-state.service.ts::stateBlocksToMessageBlocks` — its default arm surfaces unknown kinds as error blocks in front of the user, which is the only drift catch.
- **Model sources:** for Anthropic providers the composer's rows, wire ids, `Default` badge and effort stops come from `ModelPickerService` (`list_model_picker`: the list Claude Code reports for the signed-in account over `initialize`, ADR-089 and its SPEED-663 amendment); the picker is disabled while the session info is `pending`. The rows have that one source: `list_model_picker` returns `null` until the session reports its models (an idle session, the respawn window while `start_session_inner` holds the session mutex, a failed `initialize`), `ModelPickerService.refresh` then keeps the rows it already holds, and the combobox shows "Model list unavailable." with Retry when it holds none. The static catalog never supplies a row: no retired model may appear because the session has not answered yet. Every model label in the chat (picker, pill, message metadata, `/model` chip, live and rebuilt from history) goes through `ModelPickerService.label`, whose precedence is the catalog `family`, then the `display_name` Claude Code listed for a model the catalog lacks, then the id without its prefix, date and 1M suffix; nothing user-visible may contain `[1m]` or `(1M)`. `AnthropicModelsService` (`list_anthropic_models`) is metadata only: names, pricing, the effort table the slider falls back to for the current model while no rows are held. Never hard-code a model id in Angular, never build a `[1m]` id in Angular (the backend picks the wire id by plan), and never derive a context window from the catalog.
- **Routed model lists outlive the composer:** for local/OpenRouter providers the discovered rows live in `DiscoveredModelsService` (root-provided, keyed by `provider|base_url`), never in a selector-instance field — the composer is recreated on a chat-session restart or a view switch, and an instance-held list dies with it. A failed probe falls back to the last known list, rendered with the `model-selector-stale` banner and its Retry; the "Failed to load models." message with an empty list is only for a provider that was never reached, and an empty discovery result is not a fallback. A selector instance still probes once per key (`probedKey`), so a new composer instance picks up a server-side model-list change.
- **Context and plan limits:** Anthropic sessions read context usage through `ClaudeControlService.contextUsage` and plan limits through `PlanUsageService`, both pull commands on the live chat session (ADR-089). They are re-read when the session info turns `ready`, after each finished turn, on a `rate_limit_event` and when the usage popover opens, never on a timer. Missing data is hidden: no ring while the window is unknown, no plan section without limits (API-key providers never have one), never a fabricated 0% or 200k. `rate_limit_event` is a status signal only: its `utilization` is a 0-1 fraction that most events omit.
- **Beta gate:** work-in-progress Desktop surfaces ship behind the beta toggle — `BetaService` signal + the beta-enabled route guard. The flag (`ui.beta_enabled`) is user-config-only (repo `.speedwave.json` cannot set it) and is a UI visibility gate, never a security boundary. A surface that must stay usable with beta off (a running recording keeps its Stop control) needs the exception on the route guard and the keyboard shortcut too, not only on nav-rail visibility — `transcriptionRouteGuard` is the pattern.
- **Tray menu:** any new variable input to the tray menu goes into `TrayMenuState` and rebuilds through the single `refresh_tray_menu` path — a second rebuild path silently drops the other inputs.
- **Tray Icon Rules:**
  - **State Authority:** Icon is not a `TrayMenuState` input. `tray::refresh_tray_icon` queues a repaint and `apply_recording_state` re-derives icon and tooltip from live state (`transcription_cmd::DriversHandle` via `is_recording`) so both stay correct when the window is closed onto the tray. Callers only signal registry changes.
  - **Four Constraints:**
    1. Apply icon via `set_icon_with_as_template(.., true)`. Standard `set_icon` hard-resets the macOS template flag to false, breaking menu-bar adaptation (guarded by `the_repaint_reasserts_the_macos_template_flag`).
    2. Execute sampling and both applies in one `run_on_main_thread` task to prevent concurrent repaints from landing out of order. The badge pulse follows the same rule: it re-reads its generation and the registry inside its main-thread closure (guarded by `the_pulse_loop_exits_on_a_stale_generation_and_a_stopped_recording`).
    3. Route every registry mutation through `register_driver_and_repaint_tray` or `unregister_driver_and_repaint_tray` (guarded by `every_registry_mutation_repaints_the_tray`).
    4. macOS recording variant is a template image (badge renders in menu-bar tint); Windows renders a static red badge.
  - **Motion vs. Color:** macOS uses a pulsing badge (`BADGE_PULSES`, 35%-opacity second frame swapped on timer) because template rendering discards color. Windows keeps its colored badge static. Motion is used only where color is unavailable. Exactly one pulse loop may paint: every repaint bumps `BADGE_PULSE_GENERATION`, which retires the previous loop (guarded by `every_repaint_retires_the_previous_pulse_loop`).
  - **Theming:** Never derive tray appearance from `Window::theme()`. `NativeThemeAdapter.syncWindowTheme` pins it to in-app Appearance mode; Windows reads app theme rather than notification area theme.
  - **Reference:** Rationale and rejected animated indicator in ADR-056 Amendment 18.
- **CSP:** the webview CSP in `tauri.conf.json` is load-bearing on Windows (WebView2 enforces strictly; WKWebView is lenient) — e.g. `img-src 'self' blob: data:` is what makes pasted images render; changes are pinned by a test in `main.rs`.
- **TypeScript in `desktop/src` is capped by Angular's peer range** (`@angular/compiler-cli` declares it, e.g. `>=6.0 <6.1` for v22): a TypeScript bump beyond that range cannot install, so Dependabot majors for `typescript` here are rejected until an Angular major lifts the cap (`ignore` rule in `dependabot.yml`). Angular packages peer-pin each other to the exact version — bump the whole set in one PR via `ng update`, never one package.
- **`ng serve` gives a `PORT` env var priority over `angular.json` (Angular 22+)** while Tauri's `devUrl` stays fixed at the same port — `make dev` therefore launches Tauri under `env -u PORT` (guard: `_tests/desktop/dev-server-port.bats`, which also pins `angular.json` serve port ↔ `tauri.conf.json` `devUrl`). A second dev instance moves both with `make dev DEV_INSTANCE=<name>`, on a port derived from the name (ADR-031 §8).
- **`~/.claude/settings.json` in the container must stay a writable copy, not a symlink into a read-only mount** — Claude Code writes to it (`/effort`, `/model`).
- **Composer is the single model/effort control:** the model pill in the chat composer is the only place a user changes the active model or effort - Settings carries no model selector. **An Anthropic composer pick is TAB-SCOPED (ADR-092, SPEED-388), never a project write:** it wires `/model <wire id>` into the tab's live session (queued while streaming) and is recorded as the tab's model override (`ChatSessionStore.tabModel`), which every start/resume/retry of that tab passes as the `model` command param and the spawn turns into `--model` (`chat.rs::launch_model_id`: tab override > config `model_pin` > no flag). Picking the row Claude Code reports as its default sends that row's concrete wire id, so a tab returns to the account default even when a project pin exists. **The project default for new tabs is the config `model_pin`**, written only by the picker's per-row "Set default" action (`pin_cmd::set_model_pin`; the account-default row clears it via `pin_cmd::clear_model_pin`) and validated by `chat::validate_launch_model`; the container's `settings.json` `model` key is never a store: `pin_cmd::ensure_model_pin_migrated_in` strips it before every spawn, adopting its value into `model_pin` exactly once per project (the `model_pin_migrated` marker - later `model` keys are Claude Code's session-scoped `/model` persistence and must never become a default). Effort picks stay project-wide as the config `effort_pin` (`pin_cmd::set_effort_pin`, written before the wire `/effort`; the spawn passes `--effort <pin>` only when a pin exists, ADR-088 decision 5 amendment, SPEED-538); the container's `settings.json` `effortLevel` is never a second store: `pin_cmd::ensure_effort_pin_migrated_in` strips it before every spawn and on `get_effort_pin`, adopting its value only for a project without a pin, and the bundled template `containers/claude-resources/settings.json` must not seed it or `model` back, because the entrypoint merge re-adds any template key the container's file lacks (SPEED-664, guard `tests/claude_settings_template_guard.rs`); local/OpenRouter selections stay project-wide and write through to project config via the narrow `set_provider_model` command, config write before the live wire switch (ADR-088). A local/OpenRouter pick made with no live session additionally re-renders the compose and recreates the containers (`ChatStateService.rerenderContainersForModel` → `ProjectStateService.restartContainers`), because that model reaches Claude Code only as container env (`compose/llm.rs`) and the spawn carries no `--model`, while soft-impose lands too late for the first turn; a failed or already-running restart surfaces in the composer instead of respawning, and a failed one also raises the standing restart prompt so a saved-but-unapplied model stays visible (ADR-088 decision 3 amendment, SPEED-657). That respawn runs only if the chat is still unoccupied when the re-render returns (no stream, no resume, no live session): a conversation resumed while a restart runs claims the chat at once and waits until `ProjectStateService.restartInFlight` is null, including restarts that start while it waits, before replacing the session (dropped if the project changed or a switch started meanwhile), and the restart-complete resume applies only while the chat still holds the session it was decided for, also after the resume-or-fresh dialog, so none of the three replaces a session another one started. A live session still takes the wire `/model` and a mid-stream pick still defers - neither restarts a container. The badge shows the pick optimistically for every provider kind (the per-tab `ChatSessionStore.pickedModel`, fed to the selector as its `pickedModel` input - ADR-092); without that record it falls back to the model observed on the session or to the provider summary, which is reloaded only on a project change and therefore goes stale (SPEED-657).
- **Control-chip rendering is shape-based, not state-based:** a user message matching `^/(model|effort)\s+\S+$` renders as a system chip in BOTH the live stream and history reconstruction - one rule, no live-only suppression, no correlation sidecar (ADR-088). Claude Code writes an executed command to the transcript only as a synthetic `<command-name>`/`<command-args>` entry, never the typed line, so `history.rs` rebuilds the typed line from that entry before applying the rule; every other synthetic command entry stays dropped.
- **A composer effort pick never wires `/effort` into a process that holds the launch effort, and never restarts one on its own:** Claude Code refuses a wire `/effort` in a process spawned without `--effort` on a hold model (ADR-088 decision 5). `ChatStateService.applyEffortToConversation` therefore asks `get_chat_takes_wire_effort` (`ChatSession::takes_wire_effort`: a live process whose spawn carried `--effort`, read under the resolved `TabEntry`'s per-tab `start_serialize` lock and then the session lock, so a start's stop window is waited out) and wires `/effort` only when it is true; otherwise (or when the check fails) the pin is saved and `deferredEffort` drives the chat notice with Restart now (`restartForDeferredEffort` = `resumeConversation`, gated by `newConversationBlockedReason` like its button (and by the synchronous `chatBusy`), which states that background tasks stop); every spawn the frontend starts clears the notice, because it launches with the pin. Never reintroduce an automatic respawn for an effort pick: it kills a Claude Code process's between-turn work (background tasks, monitors, subagents) and races retry, rebind and mid-turn `Error` chunks. The condition is the recorded launch flag, never a list of hold models. A pick made while a turn streams or a session starts or resumes is queued and applied at the next turn end (or when the resume completes); only the latest pick is applied. An `Error` chunk releases pending model/effort picks only when the backend marks it `turn_ended` (an `is_error` result); any other `Error` can arrive mid-turn (SPEED-650).
