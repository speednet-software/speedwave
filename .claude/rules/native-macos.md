# Native macOS Rules (Swift OS integrations, TCC, transcription)

The native OS integrations (Mail, Calendar, Reminders, Notes) run as Swift CLIs on the host and drive first-party apps via AppleEvents; transcription is host-side Whisper. These carry invariants that are macOS-only and invisible from a Windows-only or test-only pass.

## AppleEvents permission gates

`native/macos/shared/Sources/SharedCLI/AppleEventsGate.swift` gates every automation target. Two-stage, PID-addressed:

- Resolve a PID via `NSWorkspace` first — if the app is not running, short-circuit to `.targetNotRunning` and send no Apple Event at all.
- Build the `AEAddressDesc` with **`typeKernelProcessID`** — never bundle-id or PSN addressing (intermittent `procNotFound -600`).
- After any `askUserIfNeeded=true` consent request (toggle click — triggers the TCC dialog, may auto-launch the target), re-read status with `askUserIfNeeded=false` as the source of truth. Mind the asymmetry: the silent `false` read cannot distinguish never-prompted from denied (both surface as `errAEEventWouldRequireUserConsent -1744` → notDetermined); only a `true` prompt yields a definitive denied (`errAEEventNotPermitted -1743`).

Extending a Mail/Notes gate or adding a new native automation gate must keep this shape — "simplifying" back to bundle-id addressing reintroduces the non-deterministic failure.

- **`ScriptRunner.run` (SharedCLI) reads `osascript`'s stdout and stderr while the script runs** (`PipeReader`), never after it exits: a script printing more than a pipe buffer (64 KB) blocks on the write and was killed at the timeout, which made `list_emails` of any mailbox with a few hundred mails fail with `MAIL_TIMEOUT` (live, 2026-10-21: Exchange Inbox of 352 mails, 1.1 s after the fix). `ScriptRunnerTests` runs scripts with 256 KB of output and of error text.

## TCC and entitlements

- macOS entitlements plists live in `desktop/src-tauri/entitlements/` (one per restricted API: apple-events, audio-capture, calendars, node, reminders, virtualization). Add a new plist for a new restricted API — never relax an existing one. The single-key shape of each plist (two keys for node, by design) and the mapping from plist to binary are a manual alignment (`.claude/rules/alignments.md`); `_tests/desktop/sign-bundled-binaries.bats` and `_tests/desktop/native-cli-info-plist.bats` only check that signing and the embedded identifiers behave correctly, not the plist content itself.
- Native CLI Info.plists must embed the computed app version (`SPEEDWAVE_VERSION`, from `crates/speedwave-version` or the env override — see `build-native-macos.sh`), correct sub-identifier, and TCC UsageDescription keys. The embedded version is test-guarded (`native-cli-info-plist.bats`, macOS-only, runs only after `make build-native-macos`); the source `Info.plist`/`Package.swift` content is a manual alignment.
- **No build step writes a native CLI `Resources/Info.plist`.** `build-native-macos.sh::stage_info_plist` copies it to `native/macos/<pkg>/.build/Info.plist` with the version substituted by `sed`, reads the copy back with `PlistBuddy -c Print` (read-only) to fail loud on a missed key, and each `Package.swift` embeds that copy with `-sectcreate`. A bare `swift build`/`swift test` therefore needs `build-native-macos.sh --stage-only` first; `make build-native-macos` and `make test-swift` do it. Guard: `_tests/desktop/build-native-macos.bats` (clean `git status` after staging).
- **Microphone consent is requested in-process by the main Tauri app** (`mic_permission_cmd.rs`, before any capture spawn), never left to a spawned CLI: `AVCaptureDevice.requestAccess` shows no prompt from a headless helper — it silently denies, with no TCC entry to re-enable. The grant lands under `pl.speedwave.desktop` and child CLIs inherit it. The main app is therefore signed with `bundle.macOS.entitlements` (`audio-capture.plist`, manual alignment) and carries `NSMicrophoneUsageDescription` in its Info.plist.

## Mail (AppleScript)

- **Apple Mail is the only mail client.** `mail-cli` drives Mail.app and nothing else. Microsoft Outlook is not a client: New Outlook has no AppleScript dictionary and Legacy Outlook no longer connects to Exchange Online, so its AppleScript path was removed (SPEED-830). `detect_clients` lists an installed Outlook (found by bundle id `com.microsoft.Outlook` through `NSWorkspace`, no Apple Event sent) as `supported: false` with `instructions` for adding the account to Apple Mail. Do not reintroduce an Outlook implementation or a `client` parameter on the mail tools; an account the user reads in Outlook is reached by adding it to Apple Mail.
- **Every mail script runs through the injected executor, within the call's time budget** (SPEED-831). `mailCommands(executor:)` in `MailCLI.swift` is the command boundary (command + JSON params to a JSON-able result); `main` passes `osascriptExecutor` (a separate `osascript` process per script, so the TCC model of ADR-049/ADR-070 is unchanged) and tests pass `FakeScriptExecutor` through `MailCommandHarness` (`Tests/MailCommandHarness.swift`), which records each script and its timeout and replays queued outputs or errors. A command that runs a script is wrapped in `scripted`, which builds `MailScripts` from the `script_timeout_ms` argument (missing or not a positive integer: refused before any script runs); never call `ScriptRunner` from a mail command. The budget has one source, `mailTimeBudget` in `mail-shared.ts`: the hub timeout (`_meta` TIMEOUT_MS) minus `PROCESS_HEADROOM_MS` is the mail-cli process timeout, minus `SCRIPT_HEADROOM_MS` the script timeout passed as `script_timeout_ms`, so the script always ends first and Swift, not Node, reports the cause. An Apple event a script sends gives up after AppleScript's default of two minutes (-1712) whatever the process timeout ("By default, when an application fails to respond to a command, AppleScript waits for two minutes", https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_control_statements.html), so `MailScripts.run` puts every `tell application "Mail"` block and one-line tell of the script inside `with timeout of <script budget, whole seconds, at least 1> seconds` (`MailScripts.withTimeout`, nesting tracked line by line, handlers included); without it the 175 s body-search script budget ended at 120 s. A script builder therefore writes `tell application "Mail"` on a line of its own (or as a one-line `tell application "Mail" to ...`) and never hides a Mail tell elsewhere; `MailCommandBoundaryTests` checks every script of every command. `MailScripts.run` turns a script timeout or AppleEvent timeout (-1712) into `MailFailure.timeout`, a denied Automation permission (`ScriptError.automationPermission` or -1743) into `.automationDenied`, and the lookup markers into the mailbox failures; any other failure keeps its real cause. A `MailFailure` prints as `<code>: <message>` (`MAIL_TIMEOUT`, `MAIL_AUTOMATION_DENIED`, `MAIL_MAILBOX_NOT_FOUND`, `MAIL_ACCOUNT_NOT_FOUND`, `MAIL_MAILBOX_AMBIGUOUS`, `MAIL_INVALID_ID`, `MAIL_NOT_FOUND`, `MAIL_MAILBOX_CHANGED`, `MAIL_BATCH_TOO_LARGE`, `MAIL_MAILBOX_EXISTS`, `MAIL_TARGET_IS_TRASH`, `MAIL_TARGET_IS_JUNK`, `MAIL_SEND_FAILED`, `MAIL_SIGNATURE_NOT_FOUND`, `MAIL_ACCOUNT_DISABLED`, `MAIL_NO_SENDER`), and `runMail` in `mail-shared.ts` turns each code into a `teachingToolResult` with the repair step (`MAIL_FAILURE_TEACHING`); a new code is added to both in the same change. `MAIL_TRASH_NOT_FOUND`, `MAIL_ALREADY_IN_TRASH`, `MAIL_JUNK_NOT_FOUND`, `MAIL_ALREADY_IN_JUNK`, `MAIL_ARCHIVE_NOT_FOUND` and `MAIL_ALREADY_ARCHIVED` only appear in a per-mail report row (mapped from their `SPW_*` markers in `MailBatch.reason`), never as a thrown failure, so they have no teaching entry. `Tests/LiveMailTests.swift` runs the real executor against Mail.app only with `SPEEDWAVE_LIVE_MAIL=1`, Mail running and an On My Mac mailbox `Speedwave-Test`, and is skipped otherwise; it is the manual pre-merge proof that the scripts work, so a ticket that changes a script adds its case there. It asks whether Mail runs with the AppleScript `application id "com.apple.mail" is running` (which launches nothing), never `NSRunningApplication`: that list only refreshes when the main run loop turns (https://developer.apple.com/documentation/appkit/nsrunningapplication), which an XCTest process does not, so the check flaked to "not running" between tests. The fake executor cannot catch AppleScript that fails at compile or run time, so non-live tests run real scripts: `ScriptCompileTests` compiles every script of every command (`Tests/EveryMailCommand.swift`, each call fed the outputs it needs, and a command that fails part way fails the test) with `osacompile` against Mail's dictionary, and `BatchRowsScriptTests` and `ListMailboxesTests` run the part of a script after its last `end tell` with `osascript` on synthetic values. Compiling a `tell application` block may send the target a get-dictionary event that launches it (https://www.macscripter.net/t/why-system-events-isnt-running/66548?page=2), unless the app ships a static dictionary, which AppleScript reads from the bundle "without launching the application" (https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptX/Concepts/scriptable_apps.html). Mail declares `OSAScriptingDefinition` `Mail.sdef`, and `ScriptCompileTests` asserts it, so the compile test needs neither a running Mail nor Automation consent on a headless runner (checked: `osacompile` of a `tell application "TV"` script, another static-sdef app, compiled its terms and left TV not running); each `osacompile` is also bounded to 60 s. Sending live tests run only with `SPEEDWAVE_LIVE_MAIL_SEND_TO`; check a send-side behaviour without sending by saving the outgoing message as a draft and reading the draft back. Deleting that draft with AppleScript `delete` only moves it to the account's Trash (live, 2026-10-20: the Exchange `Deleted Items`), where no script can erase it (see the delete bullet), so every probe leaves one message in a Trash.
- **Coerce only plain values to text.** `{item 1 of x, ...} as text` with the list literal and the coercion in one expression keeps each `item N of x` a reference and fails with -1700 ("Can't make {item 1 of {...}} into type text"); `" <" & (item 1 of email addresses of a)` fails the same way on an application list. Assign the list to a variable first (`set f to {(contents of item 1 of x) as text, ...}` then `f as text`; `set l to email addresses of a` then `item 1 of l`), and turn a date into text with `«class isot»` before joining (https://macscripter.net/t/list-iteration-issue/72151 on dereferencing with `contents of`). All of this failed live in the batch rows and the draft sender (2026-10-20).
- **A mailbox is always looked up inside an account.** Inside `tell application "Mail"`, a bare `mailbox "Archive"` is completed with the application as its container and reaches only the On My Mac mailboxes, so every account mailbox was "not found". `AppleMailClient.mailboxLookup` resolves `mailbox "<path>" of <account>` over every account plus On My Mac, or only the account named by `account`; the On My Mac mailboxes go by the pseudo-account `AppleMailClient.localAccountName` ("On My Mac"), which resolves to the app-level `mailbox "<path>"`. It sets `mb` and `spwAcctName` (the account it resolved). No match is `MailFailure.mailboxNotFound`, a name in several accounts is `MailFailure.mailboxAmbiguous` naming them (never the first match), an unknown account is `MailFailure.accountNotFound`. `list_emails` and `search_emails` require `mailbox`; the application's unified `inbox` is never read, because its messages have no single mailbox for a mail id. A nested mailbox resolves only by its path inside the account (`Inbox/Clients`), while Mail reports its `name` as the last segment, so `listMailboxes` builds `name` from `container`; it lists the app-level `mailboxes` that have no `account` under "On My Mac". It reads each account in five bulk requests, whatever its number of mailboxes: `every mailbox of`, `name of every mailbox of`, `container of every mailbox of`, `id of every message of every mailbox of` (a list per mailbox, whose length is the count; `count of messages of every mailbox` answers one total) and, app-level only, `account of every mailbox`. The paths and counts are worked out after the `tell`: a mailbox whose container `is` another listed mailbox gets that one's path in front (a container is a mailbox of class `container`, not `mailbox`, so a class test misses it; `name of container of every mailbox` answers only missing values). Lists of unequal length mean Mail changed its mailboxes between the reads (`mailboxesChangedMarker`, `MailFailure.mailboxesChanged`, `MAIL_MAILBOX_CHANGED`). Live (2026-10-20) the output equals a per-mailbox read for every account and On My Mac (`testListMailboxesGivesWhatAReadOfEachMailboxGives`); the nested-path case runs only on synthetic values (`ListMailboxesTests`), since the test Mac has no nested mailbox and a script cannot delete one it would make. A `repeat with x in <list>` loop variable is a reference: take `contents of` it before building specifiers on it.
- **Every mail is addressed by its mail id** (SPEED-832). `MailId` in `MailShared.swift` is the one encoder/decoder: `mail1.` + unpadded base64url of the JSON array `[account, mailbox path, RFC Message-ID]`, so any name or Unicode survives and the token is opaque to Claude. `list_emails` and `search_emails` emit it as `id` (with `mailbox` and `account`); a command that acts on a mail takes it as `id`, decodes it with `MailId(decoding:)` before any script runs (a bad id is `MailFailure.invalidMailId`), and finds the message with `AppleMailClient.messageLookup(_:)` (sets `mb` and `m`), passing the id's mailbox and account to `scripts.run` for the failure mapping. Never accept a raw Message-ID or look a message up in `inbox`.
- **`list_emails` reads each property of the whole mailbox with one Apple Event** (`message id of every message of mb`, likewise subject, sender, date received, read status and `flag index`; `whose read status is false` for `unread_only`, `whose flagged status is true` for `flagged_only`), never a loop of per-message events. The flag leaves the script as Mail's `flag index` (-1 unflagged, 0 to 6 the color, verified live 2026-10-21 as one bulk event answering a list of integers) and every row carries `flag`, the `mailFlagColors` name of that index or `none` for -1 and any index outside the colors (`AppleMailClient.flagName`, also used by `get_email`). The script returns the resolved account and one field per property, items joined by U+001E and fields by U+001D (`AppleMailClient.listItemSeparator`/`listFieldSeparator`); dates leave the script as `«class isot»` strings (host wall clock) and `mail-cli` emits them as ISO 8601 with the host UTC offset. Sorting newest first, `offset`/`limit` paging and `total` are done in Swift (`AppleMailClient.newestFirst`, `listEmails`); fields of unequal length mean the mailbox changed between the events (`MailFailure.mailboxChanged`).
- **`search_emails` is that same listing with a filter Mail evaluates** (SPEED-834). `AppleMailClient.MessageFilter` turns `unread_only`, `flagged_only` (`flagged status is true`, verified live as a `whose` condition), `sender`, `since`/`before` and the query into one `whose` clause shared by every property read (`listEmailsScript`), so search rows, paging and `total` are exactly those of `list_emails`. Mail's Flagged smart mailbox is not a scriptable mailbox, so counting flagged mail is one `flagged_only` listing per mailbox, reading its `total`. The query matches `subject` or `sender` only; `content` is read only with `search_body`, and then in one extra `message id of every message of mb whose ... content contains ...` request (an 8th output field, after the flag indexes) that `parseListing` intersects with the listing, because a `content` condition in the shared clause would scan every body once per property. `since`/`before` go through `parseISODateInput` in the host zone and enter the script as date variables built from calendar fields (`set year of spwSince to ...`), never a locale-dependent `date "..."` string. The body search runs under the tool's longer `BODY_SEARCH_BUDGET` (`TIMEOUT_CLASS` long), which the script's `with timeout` makes real past AppleScript's two-minute default; a subject/sender search keeps the standard budget.
- **`get_email` reads one mail with one script and returns every field Mail has for it** (SPEED-833, `MailReading.swift`): sender, `to`, `cc`, the date as ISO 8601 with the host offset (from `«class isot»`, like `list_emails`), `flag` (from `flag index of m`, named as in the listing), the plain-text body, `mailbox`/`account` from the mail id, and `attachments` (`index` = 1-based position in `mail attachments of m`, `name`, `size` when Mail knows it, `mime_type`). `include_headers`/`include_source` add `all headers of m`/`source of m`, cut inside the script at `MailReading.rawTextLimit` characters with `headers_truncated`/`source_truncated` (the TS `RAW_TEXT_LIMIT` that the tool description and schema quote is a manual alignment); the keys appear only when asked for. Fields leave the script joined by ASCII GS, list items by RS, attachment fields by US, and every free-text value goes through the script's `spwClean` handler, which strips those three characters, so a crafted subject, body or attachment name cannot forge a field. A message id no longer in its mailbox fails `messageLookup` with `mailNotFoundMarker`, reported as `MailFailure.mailNotFound` (`MAIL_NOT_FOUND`) naming the mailbox and account.
- **Mail rules are read-only, and that is a security boundary** (SPEED-841). `list_rules` (`MailRules.swift`, tool `listMailRules`) reads every rule with its conditions and actions (verified live: `rule type` and `qualifier` `as string` give names such as `from header` and `does contain value`); a condition's header is read as `«property rhed»`, because a bare `header of` does not compile against Mail's dictionary, which also has a `header` class; its script prints records separated by ASCII RS/US (`character id 30`/`31`), not `||` and newlines, because a rule's expression or reply text may contain either. No command creates, changes or deletes a rule: a prompt-injected Claude could otherwise set up permanent forwarding. `MailRulesAndCheckTests.testListRulesOnlyReadsRules` checks the script, and `mail-tools.test.ts` checks that `listMailRules` is the only tool that mentions rules. Do not add a rule-writing command without a new ADR. `check_mail` (`checkMail`) runs `check for new mail` for every account or one account by name (an unknown one is `MailFailure.accountNotFound`); Mail fetches asynchronously, so it returns `status: "started"` at once.
- **Every destructive or irreversible mail command goes through the confirmation gate, at most 25 mails per call, and reports per mail** (SPEED-835; the gate is shared, spam, send, reply, forward and redirect reuse it). `ConfirmationGate` (`MailBatch.swift`) takes a `confirm_*` param, the tool name and the question for the user: without the param set to the JSON boolean `true` the command changes nothing and answers with its preview plus `status: "confirmation_required"`, `confirm_param` and `instruction` (ask the user, call again with the flag only after a yes). A command on mails uses `MailBatch`: `ids` holds 1 to `mailBatchLimit` (25) distinct mail ids, all decoded before any script runs (one bad id, an empty list or 26 ids refuse the whole call; more than 25 is `MailFailure.batchTooLarge`, `MAIL_BATCH_TOO_LARGE`, telling Claude to split into separately confirmed batches). `MailBatch.gated` reads every mail in one script (each mail in its own `try`, so one missing mail never stops the rest), previews them unconfirmed, and confirmed runs the command's action on each and returns `MailBatch.report`: `status` `completed`/`partial`/`failed`, `succeeded`, `failed` and an `emails` row per mail with `ok` and, on failure, `error` (a `MailFailure` description such as `MAIL_NOT_FOUND`, `MAIL_TRASH_NOT_FOUND`, `MAIL_ALREADY_IN_TRASH`, or the raw cause); only a denied Automation permission or a timeout of the whole script fails the call. In `mail-organizing.ts` a gated batch tool declares `ids` with `mailIdsProperty`, its flag with `confirmProperty`, `outputSchema: gatedBatchOutputSchema()`, validates with `mailBatchError` (its `MAIL_BATCH_LIMIT` mirrors `mailBatchLimit`: manual alignment), runs on `BATCH_BUDGET` and never answers for mail-cli: the preview comes from Mail. `delete_emails` (`deleteEmails`, `destructiveHint`) moves each mail to the Trash mailbox of its own account (`moveToTrashAction`: the child of the app's `trash mailbox` whose account is the mail's, else that mailbox itself when it belongs to the account) with `move`; it never uses Mail's `delete` (an account set not to move deleted messages to the Trash would erase the mail). **Forbidden operations, by design: permanent deletion of mail, deleting or emptying a mailbox, creating or changing a rule.** The confirmation flag is set by Claude, so a prompt-injected call can bypass the preview; the Trash-only delete and the 25-mail cap bound the damage. Verified live (2026-10-20): `mailboxes of trash mailbox` lists one Trash per account (Exchange: `Deleted Items`) plus the On My Mac `Deleted Messages` once Mail has made it; reading that one's `account` errors, so the lookup assigns it to On My Mac. Before it exists, an On My Mac mail is reported `MAIL_TRASH_NOT_FOUND` and stays put; afterwards it moves there and back (both paths ran live). Mail's AppleScript `delete` of a message already in a Trash does not erase it (https://www.macscripter.net/t/mail-app-delete-selected-trashed-messages/75145) and `delete mailbox` fails with -10000 (https://www.macscripter.net/t/mail-app-delete-mailbox/74124), so a live test cannot erase what it makes. The copy/move case uses the fixed mailboxes `Speedwave-Test-copies` and `Speedwave-Test-moved`, empties both into the On My Mac Trash with `delete_emails` before it copies, and moves its copy from `-moved` to that Trash at the end, so both stay empty and `Speedwave-Test` keeps its mails; the delete and spam cases restore only from On My Mac children of the Trash or Junk. Leftovers no script can remove, each to be emptied by hand (Mailbox > Erase Deleted Items): one copy per copy/move run in the On My Mac `Deleted Messages`, one message per draft probe or draft live test in the Trash of the account that saved it, and the mailboxes `Speedwave-Test-copies`/`-moved` themselves. Copies share the original's Message-ID, so their mail ids are equal, `MailBatch` folds them into one, and a mailbox of copies empties one mail per call.
- **Reversible organizing acts at once on 1 to 25 mails; spam is gated** (SPEED-836, `MailOrganizing.swift`). `mark_emails_read` (`read`), `flag_emails` (`flag`: `mailFlagColors` in Mail's `flag index` order, 0 = red, or `none` = `flagged status` false; the TS `MAIL_FLAG_VALUES` enum in `mail-shared.ts` is a manual alignment, and it is also the enum of the `flag` key that `list_emails`, `search_emails` and `get_email` return, so one list covers the write and the read side), `move_emails`, `copy_emails` (`duplicate`) and `archive_emails` use `MailBatch.apply`: the same batch, one script and per-mail report as delete, without the gate, `WRITE_ANNOTATIONS` and `batchReportOutputSchema()`. A command's per-batch work goes in `MailAction.setup`, run once inside the `tell` before the mails: move and copy look the target up there (`mailboxLookup` with the required `account`, then `spwTarget`), so a missing target or account fails the whole call as `MAIL_MAILBOX_NOT_FOUND`/`MAIL_ACCOUNT_NOT_FOUND` naming the target, and nothing is moved. The setup also finds the target account's Trash and Junk with `accountSpecialLookup` (the lookup inside `accountSpecialMailbox`, by owner, not by name) and refuses a target that `is` one of them with `MAIL_TARGET_IS_TRASH`/`MAIL_TARGET_IS_JUNK`, whose teaching points to `deleteEmails`/`markEmailsSpam`: an ungated move or copy there would be a delete or a spam report without the user's yes. AppleScript `is` compares Mail references in the script, without an Apple event, and treats differently built references to one mailbox as equal (live: the On My Mac child of `trash mailbox` `is` `mailbox "Deleted Messages"`, the Exchange one `is` `mailbox "Deleted Items" of account`); live, a move and a copy into the On My Mac `Deleted Messages` were refused and the mail stayed. Archive moves each mail to the first of `archiveMailboxNames` (`Archive`, `[Gmail]/All Mail`) in the mail's own account (app-level for On My Mac); none is a per-mail `MAIL_ARCHIVE_NOT_FOUND`, never a move anywhere else, because Mail's scripting dictionary has no archive mailbox (`Mail.sdef` has `inbox`, `drafts mailbox`, `junk mailbox`, `outbox`, `sent mailbox` and `trash mailbox`, nothing for archive) and the archive is a per-account setting ("Archive Mailbox: Choose a mailbox on the mail server", https://support.apple.com/guide/mail/cpmlprefacctmbox/mac). The names are the server's folder names, which scripts see instead of Mail's displayed names (https://c-command.com/scripts/spamsieve/apple-mail-list-mailboxes): Gmail's archive is `[Gmail]/All Mail` (https://macscripter.net/t/archive-gmail-messages-in-mail-app/74441?page=2), the live Exchange account has `Archive`; no source gives iCloud's or a localized server's name, so the list is not extended by guess. The row error of `MAIL_ARCHIVE_NOT_FOUND` carries the repair step itself (names the mailboxes looked for, then: ask the user which mailbox keeps archived mail, `listMailboxes` lists them, and `moveEmails` there), because a per-mail row has no teaching entry. `mark_emails_spam` (`markEmailsSpam`, `destructiveHint`, `confirm_spam`) is `MailBatch.gated`: confirmed, it finds the account's Junk mailbox with `accountSpecialMailbox` (the helper the Trash lookup uses), sets `junk mail status` (trains the filter) and moves the mail there. `create_mailbox` (`createMailbox`) makes `name` (a path) in `account` (`tell account` or app-level for On My Mac) and refuses an existing one with `MailFailure.mailboxExists` (`MAIL_MAILBOX_EXISTS`). Verified live (2026-10-20): mark read and back, `flag index` set and cleared, `duplicate` into an On My Mac mailbox and `move` on, `make new mailbox` at app level for On My Mac and the exists refusal, and archive reporting `MAIL_ARCHIVE_NOT_FOUND` on On My Mac. Still unverified: the spam move (On My Mac has no Junk, so only `MAIL_JUNK_NOT_FOUND` ran; no account mail was marked as spam), and `make new mailbox` with a nested path inside `tell account`.
- **`send_email` and `reply_to_email` are gated sends of plain text** (SPEED-837, `MailSending.swift`, gate `confirm_send`). Unconfirmed, `send_email` runs one read-only script that makes no message (`senderScript`: the signature existence check when `signature` is given, then the sender) and previews `from`, `to`/`cc`/`bcc` (address lists), `subject` and `body`, plus `account` when given; `reply_to_email` runs one script that looks the mail up by its mail id (any mailbox), creates Mail's own reply (`reply m opening window false reply to all <bool>`), reads its `to`/`cc` and subject, closes it with `close ... saving no`, and reads the original's sender, date and content; the preview `body` is `MailSending.replyText`: the user's text, a blank line, `On <d MMM yyyy at HH:mm>, <sender> wrote:` and the original with every line quoted by `>`. Confirmed, the reply runs that read again and then a second script that makes a new reply, sets its `content` to exactly the previewed text and sends it, so the tool runs on `READ_THEN_SEND_BUDGET` (each script gets half the process time); the report is the preview fields with `status: "sent"`. Text enters a script through `MailSending.appleScriptText` (line breaks as `\n`, tabs as `\t`, other control characters dropped; `escapeAppleScript` alone would drop line breaks). `send` returning false is `sendFailedMarker`, `MailFailure.sendFailed` (`MAIL_SEND_FAILED`). No HTML (Mail's `html content` does nothing) and no attachments yet; the schemas promise neither. Verified live (2026-10-20/21): a windowless reply closed with `close ... saving no` leaves no draft, and `content` set on a reply replaces Mail's own quote; `send_email` and a reply to a mail from the test address were sent to `SPEEDWAVE_LIVE_MAIL_SEND_TO` and arrived in Sent with the reply's `In-Reply-To`/`References`. **Mail shows any text a script sets as a quote** (Mail 16 on macOS 27.0.1, live 2026-10-21): the sent or saved source carries the text as `> ` lines in `text/plain` and inside `<blockquote type="cite">` under `Apple-Mail-URLShareWrapperClass` in `text/html`, while `content` read back shows plain text, so check the `source` of the Sent or Drafts copy, never `content`. Apple's open report FB11734014 (https://developer.apple.com/forums/thread/738842). Every object-model variant tried wraps it: `content` in the `make` properties or set after, `visible` true or false, `make new paragraph`, `html content`. Only Mail's `mailto` command composes plain text, but it opens a window that is no `outgoing message` and that a script can neither send nor close (https://github.com/sfls1397/Apple-Tools-MCP/pull/13, and live). The other way out is pasting through System Events, which needs the Accessibility permission for the host worker and takes over the clipboard; it was rejected for the security model. So `send_email`, `reply_to_email` and `save_draft` keep the quote (user decision 2026-10-21) and their tool descriptions and the skill tell Claude to warn the user; forward and redirect never set text and are not affected.
- **`forward_email` and `redirect_email` pass a mail on behind the same `confirm_send` gate** (SPEED-838, `MailSending.forwardEmail`/`redirectEmail`, gates `forwardGate`/`redirectGate`). Both take `id`, `to` and optional `cc` (no bcc), and nothing else: neither takes a comment. Both first run one read script over the mail id: the outgoing subject (forward: Mail's own `forward m opening window false`, its subject read, then `close ... saving no`; redirect: the original's subject, no redirect made), the original's subject, sender and date, and the names of its `mail attachments`. Preview and report share `{to, cc, subject, original: {id, subject, sender, date?, mailbox, account}, attachments: [names]}`; the report adds `status: "sent"`. Confirmed, a second script makes Mail's forward or redirect again, adds the recipients and sends it, so both run on `READ_THEN_SEND_BUDGET`. Neither script ever changes the outgoing message's text: verified live on 2026-10-20 (drafts saved and read back, nothing sent), any change to a forward's content (`make new paragraph at beginning of content`, `set content`, `make new character`, with or without a window) leaves only the inserted text, the quote and the attachments gone, as reported at https://www.macscripter.net/t/forward-mail-in-mail-app-and-adding-attachment-deletes-existing-message-body/77022; so `forward_email` has no `comment` parameter (user decision) and a note goes in a separate email. Verified live the same way: an untouched windowless `forward m opening window false`, saved, carries Mail's full quote and the original's attachment, and a windowless forward or reply closed with `close ... saving no` leaves no draft. A redirect never touches subject or content; saved as a draft (live, 2026-10-20) its recipients become `Resent-To` with `Resent-From` the user, while `From`, `To` and the text stay the original's. Both were also sent live to `SPEEDWAVE_LIVE_MAIL_SEND_TO` (2026-10-21) and their Sent copies carry Mail's own quote (forward) or the original unchanged (redirect), with no added quote wrapper.
- **Drafts are ungated, signatures are checked before anything goes out** (SPEED-839, `MailSending.swift`). `save_draft` (`saveDraft`, `WRITE_ANNOTATIONS`, no `confirm_*`: a draft is reversible) builds the same new-message script as `send_email` (`newMessageScript`) but ends with `save spwMsg` and `close spwMsg saving yes` instead of `send`; `to` and `body` are optional. **The sender is read from Mail and always set** (SPEED-850): `send_email` and `save_draft` take `account`, and one helper, `MailSending.senderLines`, picks the sender for the preview script and the new-message script alike, before the message exists. With `account` it checks the account exists (`accountNotFoundMarker`, `MailFailure.accountNotFound`) and is turned on, and takes its `full name` and first `email addresses` item; without it, it takes Mail's `primary email` when a turned-on account has that address, else the first address of the first turned-on account; no address at all is `noSenderMarker`, `MailFailure.noSender` (`MAIL_NO_SENDER`). The new-message script sets the message's `sender` to that `Name <address>` (so Mail files a draft in that account's Drafts, and a send cannot fall back to another account) and returns it, cleaned by `spwClean`, as `from` of the report; the preview's `from` comes from the same lines. Live, Mail silently ignores a `sender` of no account and uses its default, which is why the sender is always one Mail has. Unverified live: that `primary email` is the address Mail would pick on its own (`LiveMailTests` compares the preview's `from` with the sender of the same message saved as a draft). `list_signatures` (`listMailSignatures`, read-only) returns the signature names, cleaned by `spwClean` and joined by RS. `send_email`, `reply_to_email` and `save_draft` take `signature`: every script of the call starts with `if not (exists signature ...) then error signatureNotFoundMarker` (`MailFailure.signatureNotFound`, `MAIL_SIGNATURE_NOT_FOUND`), so an unconfirmed send with a signature runs that one check script, and the sending script sets `message signature` before `send`/`save`; the preview and report carry `signature` only when one was chosen (Mail adds the signature's text, which the preview `body` does not show, so the skill tells Claude to name it to the user). Without `signature` the new-message and reply-send scripts set `message signature` to `missing value`, which `Mail.sdef` allows (type `signature` or `missing value`) and which ran live on a saved draft, so Mail cannot add the account's default signature unpreviewed. Whether Mail adds that default to a scripted message at all is reported both ways (not added, "broken since Tiger": https://www.macscripter.net/t/setting-the-signature-for-a-new-message-in-apple-mail/71752; added and then overwritten by the scripted content: https://www.macscripter.net/t/use-default-signature-in-new-mail-message/62300), hence the explicit clear. Forward and redirect never touch it, since any change to a forward empties it. No attachments: the host-side mcp-os cannot tell which project called it (SPEED-842). A turned-off account is refused before the message is made, by a send and a draft alike (`if not (enabled of spwAccount)`, `MailFailure.accountDisabled`, `MAIL_ACCOUNT_DISABLED`): live, Mail ignored a `sender` of a turned-off account, given before or after `make`, and filed the draft in the default account under the default address. Verified live (2026-10-20): `save` + `close saving yes` leaves exactly one draft, unsent, in the Drafts of the enabled account named, with its address as sender and the body's line breaks; the test Mac has one enabled account, so filing into a non-default account's Drafts is unverified. Unverified live: any `message signature` (the test Mail has no signature), on a new message, a windowless reply or after `content`.
- **The TS mail tools mirror the Swift split**: `mail-shared.ts` (time budget, `runMail`, `MAIL_FAILURE_TEACHING`, schema pieces several modules use), `mail-reading.ts` (clients, mailboxes, list, get, search), `mail-organizing.ts` (the batch tools and `createMailbox`), `mail-sending.ts` (send, reply, forward, redirect, drafts, signatures), `mail-rules.ts` (rules, check mail); `mail-tools.ts` only assembles them in `createMailTools`. A module exports only what another module imports (its tools and handlers); tests stay in `mail-tools.test.ts` and import the handlers from their module.
- **The mail tools reject undeclared arguments** (`withDeclaredParams` in `mail-tools.ts`), so a `client` argument fails with a teaching error instead of being dropped by `mail-cli`. A new parameter is declared in the same change that makes `mail-cli` read it.
- **`outputSchema` mirrors what `mail-cli` prints**, nesting included (`getEmail` returns `{ email: {...} }`), with `read` a boolean, `message_count` and `total` numbers (`AppleMailClient.ListedMessage.json`/`parseMailboxes`); `mail-tools.test.ts` compares the key tree of each tool's schema with a sample of the CLI's output. A key added to a Swift result is declared in the schema and in that sample in the same change.

## Reminders (EventKit)

- **Public EventKit only.** `reminders-cli` talks to `EKEventStore` and nothing else: no AppleScript, no reading the Reminders SQLite store (needs Full Disk Access), no private ReminderKit. Consequence: flags, native tags, subtasks, sections, images and smart lists are out of reach; "tags" are `[#tag]` markers inside the notes field (`combineTags`/`extractTags`/`stripTags`), parsed back into a separate `tags` array.
- **Glossary** (tool params, schemas and docs use these words): _list_ = an `EKCalendar` that holds reminders (never "calendar"); _reminder_; _tag_ = a `[#tag]` marker; _due date_ is _all-day_ (`YYYY-MM-DD`, components without time fields) or _timed_, and always _floating_ (`timeZone == nil`: 9:00 stays 9:00 in every zone); _alarm_ (not alert/notification); _recurrence_ (not repeat); _completed_.
- **Due dates go through `dueDateComponents(from:timeZone:)`/`dueDateString(from:timeZone:)`** in `RemindersCLI.swift`; `timeZone` defaults to the host zone and exists so tests pin explicit zones (CI runners sit in UTC, where an offset conversion is indistinguishable from none). Input: `YYYY-MM-DD` (all-day), `YYYY-MM-DDTHH:MM:SS` (kept as typed, never resolved through the host zone, so a DST-gap time stays what the user asked for) or the same with an offset/`Z` (converted to host wall clock); anything else, including unpadded dates and impossible dates, is rejected. The components always carry the Gregorian calendar (EventKit raises otherwise, and `Calendar.current` need not be Gregorian) and no time zone. Output: `YYYY-MM-DD` or local time with an explicit UTC offset (`+00:00`, never `Z`, via SharedCLI `iso8601String(from:timeZone:)`), plus `all_day`; `completed_date` is local time with offset.
- **One date parser for both EventKit CLIs:** SharedCLI `parseISODateInput` classifies input as a bare day, a wall-clock time or an instant (strict, zero-padded, impossible dates rejected). Reminders map it to floating components (above); `calendar-cli` resolves it with `eventDate(from:timeZone:)`: a bare day is local midnight, a wall-clock time is local time, an instant is kept. Event output stays UTC with `Z`. `parseISO8601` accepts instants only: its old bare-date fallback turned `2026-06-15` into UTC midnight, which is the previous evening west of UTC, so never route a bare day through it.
- **`update_reminder` is a PATCH:** an omitted field keeps its value; JSON `null` on `due_date` clears the due date and drops the recurrence rules with it (EventKit refuses a recurring reminder without a due date). `notes` and `tags` share one EventKit field; `mergeNotes` replaces only the side the caller sent and keeps the other byte-for-byte (`tags: []` clears tags); `completed: false` reopens. A `list_id` that names several lists is refused (`CLIError.ambiguous`), never resolved to the first match; the same SharedCLI `resolveSingleCalendar` guards the target calendar of `create_event`. Listing (`list_reminders`, `list_events`) still merges every calendar a shared name matches.

## Transcription

- Fully local: raw audio and transcript passes never leave the machine (see security rules — this is a privacy invariant, not just a design choice).
- Models are auto-selected per pass from the runtime GPU class (`accel.rs`: Metal on macOS, Vulkan on Windows — ADR-085; CUDA deferred). No user model picker — do not add one. macOS asserts `GpuClass::Discrete` rather than probing; a Metal init failure falls back inside whisper.cpp (visible in logs via the routed whisper hooks).
- No speaker diarization — deliberately removed as inherently unreliable (ADR-075, which also removed sherpa-onnx and every Windows CRT workaround with it; see cross-platform rules). Do not reintroduce diarization or swap in another engine.
