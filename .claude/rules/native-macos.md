# Native macOS Rules (Swift OS integrations, TCC, transcription)

The native OS integrations (Mail, Calendar, Reminders, Notes) run as Swift CLIs on the host and drive first-party apps via AppleEvents; transcription is host-side Whisper. These carry invariants that are macOS-only and invisible from a Windows-only or test-only pass.

## AppleEvents permission gates

`native/macos/shared/Sources/SharedCLI/AppleEventsGate.swift` gates every automation target. Two-stage, PID-addressed:

- Resolve a PID via `NSWorkspace` first — if the app is not running, short-circuit to `.targetNotRunning` and send no Apple Event at all.
- Build the `AEAddressDesc` with **`typeKernelProcessID`** — never bundle-id or PSN addressing (intermittent `procNotFound -600`).
- After any `askUserIfNeeded=true` consent request (toggle click — triggers the TCC dialog, may auto-launch the target), re-read status with `askUserIfNeeded=false` as the source of truth. Mind the asymmetry: the silent `false` read cannot distinguish never-prompted from denied (both surface as `errAEEventWouldRequireUserConsent -1744` → notDetermined); only a `true` prompt yields a definitive denied (`errAEEventNotPermitted -1743`).

Extending a Mail/Notes gate or adding a new native automation gate must keep this shape — "simplifying" back to bundle-id addressing reintroduces the non-deterministic failure.

- **`ScriptRunner.run` (SharedCLI) reads `osascript`'s stdout and stderr while the script runs** (`PipeReader`, which drains each pipe on a background queue from the moment it is made), never after it exits: a script printing more than a pipe buffer (64 KB) blocks on the write and was killed at the timeout, which made `list_emails` of any mailbox with a few hundred mails fail with `MAIL_TIMEOUT` (live, 2026-10-21: Exchange Inbox of 352 mails, 1.1 s after the fix). `ScriptRunnerTests` runs scripts with 256 KB of output and of error text. The script itself goes to `osascript` on stdin (no `-e`), written on a background queue into a pipe marked `F_SETNOSIGPIPE`: an `-e` argument is bound by the argument limit (`ARG_MAX`, 1 MB on macOS, environment included), so a reply quoting a mail of about 1 MB failed with E2BIG before the script ran. `ScriptRunnerTests` runs a 2 MB script with Unicode text.

## TCC and entitlements

- macOS entitlements plists live in `desktop/src-tauri/entitlements/` (one per restricted API: apple-events, audio-capture, calendars, node, reminders, virtualization). Add a new plist for a new restricted API — never relax an existing one. The single-key shape of each plist (two keys for node, by design) and the mapping from plist to binary are a manual alignment (`.claude/rules/alignments.md`); `_tests/desktop/sign-bundled-binaries.bats` and `_tests/desktop/native-cli-info-plist.bats` only check that signing and the embedded identifiers behave correctly, not the plist content itself.
- Native CLI Info.plists must embed the computed app version (`SPEEDWAVE_VERSION`, from `crates/speedwave-version` or the env override — see `build-native-macos.sh`), correct sub-identifier, and TCC UsageDescription keys. The embedded version is test-guarded (`native-cli-info-plist.bats`, macOS-only, runs only after `make build-native-macos`); the source `Info.plist`/`Package.swift` content is a manual alignment.
- **No build step writes a native CLI `Resources/Info.plist`.** `build-native-macos.sh::stage_info_plist` copies it to `native/macos/<pkg>/.build/Info.plist` with the version substituted by `sed`, reads the copy back with `PlistBuddy -c Print` (read-only) to fail loud on a missed key, and each `Package.swift` embeds that copy with `-sectcreate`. A bare `swift build`/`swift test` therefore needs `build-native-macos.sh --stage-only` first; `make build-native-macos` and `make test-swift` do it. Guard: `_tests/desktop/build-native-macos.bats` (clean `git status` after staging).
- **Microphone consent is requested in-process by the main Tauri app** (`mic_permission_cmd.rs`, before any capture spawn), never left to a spawned CLI: `AVCaptureDevice.requestAccess` shows no prompt from a headless helper — it silently denies, with no TCC entry to re-enable. The grant lands under `pl.speedwave.desktop` and child CLIs inherit it. The main app is therefore signed with `bundle.macOS.entitlements` (`audio-capture.plist`, manual alignment) and carries `NSMicrophoneUsageDescription` in its Info.plist.

## Mail (AppleScript)

- **Apple Mail is the only mail client.** `mail-cli` drives Mail.app and nothing else. Microsoft Outlook is not a client: New Outlook has no AppleScript dictionary and Legacy Outlook no longer connects to Exchange Online, so its AppleScript path was removed (SPEED-830). `detect_clients` lists an installed Outlook (found by bundle id `com.microsoft.Outlook` through `NSWorkspace`, no Apple Event sent) as `supported: false` with `instructions` for adding the account to Apple Mail. Do not reintroduce an Outlook implementation or a `client` parameter on the mail tools; an account the user reads in Outlook is reached by adding it to Apple Mail.
- **Every mail script runs through the injected executor, within the call's time budget** (SPEED-831). `mailCommands(executor:)` in `MailCLI.swift` is the command boundary (command + JSON params to a JSON-able result); `main` passes `osascriptExecutor` (a separate `osascript` process per script, so the TCC model of ADR-049/ADR-070 is unchanged) and tests pass `FakeScriptExecutor` through `MailCommandHarness` (`Tests/MailCommandHarness.swift`), which records each script and its timeout and replays queued outputs or errors. A command that runs a script is wrapped in `scripted`, which builds `MailScripts` from the `script_timeout_ms` argument (missing or not a positive integer: refused before any script runs); never call `ScriptRunner` from a mail command. The budget has one source, `mailTimeBudget` in `mail-shared.ts`: the hub timeout (`_meta` TIMEOUT_MS) minus `PROCESS_HEADROOM_MS` is the mail-cli process timeout, minus `SCRIPT_HEADROOM_MS` the script timeout passed as `script_timeout_ms`, so the script always ends first and Swift, not Node, reports the cause. An Apple event a script sends gives up after AppleScript's default of two minutes (-1712) whatever the process timeout ("By default, when an application fails to respond to a command, AppleScript waits for two minutes", https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_control_statements.html), so `MailScripts.run` puts every `tell application "Mail"` block and one-line tell of the script inside `with timeout of <script budget, whole seconds, at least 1> seconds` (`MailScripts.withTimeout`, nesting tracked line by line, handlers included); without it the 175 s body-search script budget ended at 120 s. A script builder therefore writes `tell application "Mail"` on a line of its own (or as a one-line `tell application "Mail" to ...`) and never hides a Mail tell elsewhere; `MailCommandBoundaryTests` checks every script of every command. `MailScripts.run` turns a script timeout or AppleEvent timeout (-1712) into `MailFailure.timeout`, a denied Automation permission (`ScriptError.automationPermission` or -1743) into `.automationDenied`, and the lookup markers into the mailbox failures; any other failure keeps its real cause. A `MailFailure` prints as `<code>: <message>` (`MAIL_TIMEOUT`, `MAIL_AUTOMATION_DENIED`, `MAIL_MAILBOX_NOT_FOUND`, `MAIL_ACCOUNT_NOT_FOUND`, `MAIL_ACCOUNT_AMBIGUOUS`, `MAIL_MAILBOX_AMBIGUOUS`, `MAIL_INVALID_ID`, `MAIL_NOT_FOUND`, `MAIL_MAILBOX_CHANGED`, `MAIL_BATCH_TOO_LARGE`, `MAIL_MAILBOX_EXISTS`, `MAIL_TARGET_IS_TRASH`, `MAIL_TARGET_IS_JUNK`, `MAIL_SPECIAL_MAILBOX`, `MAIL_SEND_FAILED`, `MAIL_PREVIEW_CHANGED`, `MAIL_SIGNATURE_NOT_FOUND`, `MAIL_ACCOUNT_DISABLED`, `MAIL_NO_SENDER`), and `runMail` in `mail-shared.ts` turns each code into a `teachingToolResult` with the repair step (`MAIL_FAILURE_TEACHING`); a new code is added to both in the same change. The `MAIL_TIMEOUT` step depends on the command (`mail-shared.ts::timeoutStep`): a list or search is narrowed with its filters or one mailbox, since `limit` and `offset` are applied in Swift after Mail answered and never shorten a Mail request; a command that changes mail is never retried, because part of it may have happened (a batch may have changed some mails and a repeated copy makes second copies, a send may have gone out, a draft been saved, a mailbox created or renamed), so Claude checks the mailboxes, Sent, Drafts or `listMailboxes` and tells the user. Every `MAIL_TIMEOUT` teaching ends with `mail-shared.ts::STUCK_MAIL_STEP`: after a second mail timeout in one conversation Claude stops calling mail tools and asks the user to quit and reopen Mail.app, since Mail may have stopped answering (see the compose-thread leak bullet below). A mailbox or account failure of a call that names its mail by `id` or `ids` and has no `mailbox` (`staleMailIdTeaching`) is taught as an out-of-date mail id to list again, never as a `mailbox` or `account` parameter the tool does not take. `MAIL_TRASH_NOT_FOUND`, `MAIL_ALREADY_IN_TRASH`, `MAIL_JUNK_NOT_FOUND`, `MAIL_ALREADY_IN_JUNK`, `MAIL_ARCHIVE_NOT_FOUND`, `MAIL_ALREADY_ARCHIVED` and `MAIL_NOT_ATTEMPTED` only appear in a per-mail report row (mapped from their `SPW_*` markers in `MailBatch.reason`), never as a thrown failure, so they have no teaching entry. `Tests/LiveMailTests.swift` runs the real executor against Mail.app only with `SPEEDWAVE_LIVE_MAIL=1`, Mail running and an On My Mac mailbox `Speedwave-Test`, and is skipped otherwise; it is the manual pre-merge proof that the scripts work, so a ticket that changes a script adds its case there. It asks whether Mail runs with the AppleScript `application id "com.apple.mail" is running` (which launches nothing), never `NSRunningApplication`: that list only refreshes when the main run loop turns (https://developer.apple.com/documentation/appkit/nsrunningapplication), which an XCTest process does not, so the check flaked to "not running" between tests. The fake executor cannot catch AppleScript that fails at compile or run time, so non-live tests run real scripts: `ScriptCompileTests` compiles every script of every command (`Tests/EveryMailCommand.swift`, each call fed the outputs it needs, and a command that fails part way fails the test) with `osacompile` against Mail's dictionary, and `BatchRowsScriptTests` and `ListMailboxesTests` run the part of a script after its last `end tell` with `osascript` on synthetic values. Compiling a `tell application` block may send the target a get-dictionary event that launches it (https://www.macscripter.net/t/why-system-events-isnt-running/66548?page=2), unless the app ships a static dictionary, which AppleScript reads from the bundle "without launching the application" (https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptX/Concepts/scriptable_apps.html). Mail declares `OSAScriptingDefinition` `Mail.sdef`, and `ScriptCompileTests` asserts it, so the compile test needs neither a running Mail nor Automation consent on a headless runner (checked: `osacompile` of a `tell application "TV"` script, another static-sdef app, compiled its terms and left TV not running); each `osacompile` is also bounded to 60 s. Sending live tests run only with `SPEEDWAVE_LIVE_MAIL_SEND_TO`; check a send-side behaviour without sending by saving the outgoing message as a draft and reading the draft back. Deleting that draft with AppleScript `delete` only moves it to the account's Trash (live, 2026-10-20: the Exchange `Deleted Items`), where no script can erase it (see the delete bullet), so every probe leaves one message in a Trash.
- **Coerce only plain values to text.** `{item 1 of x, ...} as text` with the list literal and the coercion in one expression keeps each `item N of x` a reference and fails with -1700 ("Can't make {item 1 of {...}} into type text"); `" <" & (item 1 of email addresses of a)` fails the same way on an application list. Assign the list to a variable first (`set f to {(contents of item 1 of x) as text, ...}` then `f as text`; `set l to email addresses of a` then `item 1 of l`), and turn a date into text with `«class isot»` before joining (https://macscripter.net/t/list-iteration-issue/72151 on dereferencing with `contents of`). All of this failed live in the batch rows and the draft sender (2026-10-20).
- **A list a script loops over lives in a script object.** AppleScript reads `item i` of a list held in a variable (a handler parameter, a local, or a variable of the top-level run handler) and appends to one with `set end of` in time proportional to the list's length, so a loop over a list is quadratic: `spwCounts` took about 26 s for 6,000 items and the old per-mailbox path handler 16 s for 800 mailboxes (measured with `osascript`, 2026-10-22). A handler therefore copies its lists into properties of a local `script` object (`property spwS : spwList`) and reads and appends through it (`item i of spwO's spwS`, `set end of spwO's spwR`), which took 0.03 s for the same 6,000 items. `ListingScriptTests` runs the post-`tell` part of `list_emails` with 6,000 synthetic mails and of `list_mailboxes` with 800 nested mailboxes through `osascript` and requires each under a third of the harness's 25 s script budget (0.8 s and 0.3 s on an idle Mac, about 5 s and 1.6 s under heavy load; the quadratic versions took 29 s and 16 s).
- **A mailbox is always looked up inside an account.** Inside `tell application "Mail"`, a bare `mailbox "Archive"` is completed with the application as its container and reaches only the On My Mac mailboxes, so every account mailbox was "not found". `AppleMailClient.mailboxLookup` resolves `mailbox "<path>" of <account>` over every account plus On My Mac, or only the account named by `account`; the On My Mac mailboxes go by the pseudo-account `AppleMailClient.localAccountName` ("On My Mac"), which resolves to the app-level `mailbox "<path>"`. It sets `mb`, `spwAcct` (missing value for On My Mac), `spwAcctName` and `spwAcctId` (the account's Mail `id`, "" for On My Mac). No match is `MailFailure.mailboxNotFound`, a name in several accounts is `MailFailure.mailboxAmbiguous` naming them (never the first match), an unknown account is `MailFailure.accountNotFound`. **An account the user names is resolved by name only through `AppleMailClient.accountLookup`** (`every account whose name is "<name>"`): no match is `accountNotFoundMarker`, several are `accountAmbiguousMarker`, `MailFailure.accountAmbiguous` (`MAIL_ACCOUNT_AMBIGUOUS`, whose teaching asks the user to give one account another description in Mail > Settings > Accounts), never the first or last match, since Mail allows two accounts with one name and a wrong pick could move a mail into another server's Trash. Every command that takes an `account` (list, search, move/copy target, create, rename, send, draft, check mail) goes through it; an account is never addressed as `account "<name>"`. Verified live (2026-10-22, one Exchange account): `id of account` is a UUID text, `account id "<id>"` and `exists account id` resolve it, and `every account whose name is` answers a list. `list_emails` requires `mailbox`, and `search_emails` either takes one or searches every mailbox (next bullets but one); the application's unified `inbox` is never read, because its messages have no single mailbox for a mail id. A nested mailbox resolves only by its path inside the account (`Inbox/Clients`), while Mail reports its `name` as the last segment, so `listMailboxes` builds `name` from `container`; it lists the app-level `mailboxes` that have no `account` under "On My Mac". It reads each account in six bulk requests, whatever its number of mailboxes: `every mailbox of`, `name of every mailbox of`, `container of every mailbox of`, `id of every message of every mailbox of` (a list per mailbox, whose length is the count; `count of messages of every mailbox`, `count of every message of every mailbox` and `count (messages of every mailbox)` each answer one total, live 2026-10-22, and the id read took under a second for 1,712 mails), `unread count of every mailbox of` (one number per mailbox, verified live 2026-10-21 as one bulk read, emitted as `unread_count`) and, app-level only, `account of every mailbox`. The paths and counts are worked out after the `tell`, the paths by the AppleScript handler `AppleMailClient.mailboxPathsHandler` (`spwMailboxPaths`, placed after the script's statements, shared with the all-mailbox search), which finds each mailbox's parent once and then builds every path: a mailbox whose container `is` another listed mailbox gets that one's path in front (a container is a mailbox of class `container`, not `mailbox`, so a class test misses it; `name of container of every mailbox` answers only missing values). The rows leave the script as records joined by ASCII RS with fields joined by US, and names pass through `spwTexts`, so a name with `||`, a line break or a separator character stays one name. Lists of unequal length mean Mail changed its mailboxes between the reads (`mailboxesChangedMarker`, `MailFailure.mailboxesChanged`, `MAIL_MAILBOX_CHANGED`). Live (2026-10-20) the output equals a per-mailbox read for every account and On My Mac (`testListMailboxesGivesWhatAReadOfEachMailboxGives`); the nested-path case runs only on synthetic values (`ListMailboxesTests`), since the test Mac has no nested mailbox and a script cannot delete one it would make. A `repeat with x in <list>` loop variable is a reference: take `contents of` it before building specifiers on it.
- **Every mail is addressed by its mail id** (SPEED-832). `MailId` in `MailShared.swift` is the one encoder/decoder: `mail2.` + unpadded base64url of the JSON array `[account id, account name, mailbox path, RFC Message-ID]` (the account id "" for On My Mac), so any name or Unicode survives, two accounts with one name give one mail two ids, and the token is opaque to Claude. `mail1.` ids (no account id) were never released and are refused as `MAIL_INVALID_ID`. `AppleMailClient.messageLookup` resolves the id's account by `account id "<id>"` (`mailboxLookup(path:accountId:)`), never by name, and sets the same variables as `mailboxLookup`. `list_emails` and `search_emails` emit it as `id` (with `mailbox` and `account`); the TS tools accept ids up to `mail-shared.ts::MAIL_ID_MAX_LENGTH` (8,192), since a long Message-ID in a deep mailbox outgrew the shared 512-character id cap; a command that acts on a mail takes it as `id`, decodes it with `MailId(decoding:)` before any script runs (a bad id is `MailFailure.invalidMailId`), and finds the message with `AppleMailClient.messageLookup(_:)` (sets `mb` and `m`), passing the id's mailbox and account to `scripts.run` for the failure mapping. Never accept a raw Message-ID or look a message up in `inbox`.
- **`list_emails` reads each property of the whole mailbox with one Apple Event** (`message id of every message of mb`, likewise subject, sender, date received, read status and `flag index`; `whose read status is false` for `unread_only`, `whose flagged status is true` for `flagged_only`), never a loop of per-message events. The flag leaves the script as Mail's `flag index` (-1 unflagged, 0 to 6 the color, verified live 2026-10-21 as one bulk event answering a list of integers) and every row carries `flag`, the `mailFlagColors` name of that index or `none` for -1 and any index outside the colors (`AppleMailClient.flagName`, also used by `get_email`). The script returns the resolved account and one field per property, items joined by U+001E and fields by U+001D (`AppleMailClient.listItemSeparator`/`listFieldSeparator`); the Message-ID, subject and sender columns pass through the `spwTexts` handler, which turns missing values into empty text and, only when the joined column holds one of FS, GS, RS or US, strips them from every item with `spwClean` (the account name and every mailbox path go through `spwClean` too), so a crafted subject cannot split a row; dates leave the script as `«class isot»` strings (host wall clock) and `mail-cli` emits them as ISO 8601 with the host UTC offset. Sorting newest first, `offset`/`limit` paging and `total` are done in Swift (`AppleMailClient.newestFirst`, `listEmails`); `offset` and `limit` must be whole numbers on both sides (TS `integers`, Swift `MailCLI.wholeNumberParam`, which refuses a fraction, text or a boolean instead of falling back to the default, as `as? Int` did), and `since`/`before` are checked as ISO 8601 dates in TS before mail-cli parses them; the hub's `paginate()` reads a listing's `emails` (`hub/src/paginate.ts::ITEM_KEYS`); the read-status column, never empty for a mail, gives the number of mails. A mail without a Message-ID header (an empty or missing `message id`) cannot be named by a mail id, so it is left out of `emails` and `total` and counted in `without_id`, a key present only when it is above 0; fields of unequal length mean the mailbox changed between the events (`MailFailure.mailboxChanged`). Every row carries `attachment_count` (SPEED-849): `name of mail attachments of (<scope>)` answers one list of names per message in one event (verified live 2026-10-21 unfiltered, about 20 ms for 352 mails; `count of mail attachments of every message` answers one total instead), and the script's `spwCounts` handler (in `AppleMailClient.listingHandlers`, with `spwIsoTexts`, which turns the dates into `«class isot»` text) turns it into a count per message. The columns a listing reads, their order in the output and the handler that turns each into text come from one list, `AppleMailClient.listedColumns`: `listEmailsScript`, `searchAllMailboxesScript` and the parsers' field counts are generated from it, so a column is added there and in `parseListing` only. The scope is parenthesized because a `whose` clause filters the outermost element class of a reference: `name of every disk item of every folder of X whose name starts with "a"` filters the disk items, `name of every disk item of (every folder of X whose ...)` the folders (probed with System Events, 2026-10-21), so without the parentheses Mail would apply the message conditions to attachments. The same rule is why `<property> of every message of every mailbox of <account> whose ...` filters messages. Mail likely counts images embedded in the text too (live: 197 of 352 mails had one), so the tool descriptions say `getEmail` gives the exact list. Unverified live: the parenthesized filtered scope in Mail, and the three-level answer (per mailbox, per message) of the all-mailbox search.
- **`search_emails` is that same listing with a filter Mail evaluates** (SPEED-834). `AppleMailClient.MessageFilter` turns `unread_only`, `flagged_only` (`flagged status is true`, verified live as a `whose` condition), `sender`, `recipient`, `since`/`before` and the query into one `whose` clause shared by every property read (`listEmailsScript`), so search rows, paging and `total` are exactly those of `list_emails`. `recipient` (SPEED-847) is `((address of every to recipient) contains "<address>" or (address of every cc recipient) contains "<address>")`: a list-membership test, so it matches a whole address only; the To half is verified live (2026-10-21, 12 hits in Exchange Sent Items), the Cc half is not yet (`LiveMailTests` has a case). The query is optional, but a search needs at least one filter (`MessageFilter.narrows`, else `MailError.noSearchFilter` pointing to `list_emails`; the TS handler refuses it first, `MISSING_FIELDS` pointing to `listEmails`, with the filters of `mail-reading.ts::SEARCH_FILTERS`, which `mail-cli-commands.test.ts` compares with `narrows` and the `noSearchFilter` text), and `search_body` still needs the query. Mail's Flagged smart mailbox is not a scriptable mailbox, so counting flagged mail is one `flagged_only` search without `mailbox` (next bullet), reading its `total`; with `mailbox` it counts that mailbox. The query matches `subject` or `sender` only; `content` is read only with `search_body`, and then in one extra `message id of every message of mb whose ... content contains ...` request (a 9th output field, after the attachment counts) that `parseListing` intersects with the listing, because a `content` condition in the shared clause would scan every body once per property. `since`/`before` go through `parseISODateInput` in the host zone and enter the script as date variables built from calendar fields (`set year of spwSince to ...`), never a locale-dependent `date "..."` string. The body search runs under the tool's longer `BODY_SEARCH_BUDGET` (`TIMEOUT_CLASS` long), which the script's `with timeout` makes real past AppleScript's two-minute default; a subject/sender search keeps the standard budget.
- **`search_emails` without `mailbox` searches every mailbox in one script** (SPEED-848, `AppleMailClient.searchAllMailboxesScript`): every mailbox of `account`, of the On My Mac mailboxes for `localAccountName`, or of every account plus On My Mac without `account`. Each account costs the three `listMailboxes` reads (`every mailbox of`, `name of`, `container of`, built by `AppleMailClient.mailboxReads` for both scripts; app-level also `account of every mailbox`, whose non-missing entries are left out as in `listMailboxes`) plus one `<property> of every message of every mailbox of spwAcct whose ...` event per listed property, which answers one list per mailbox in the order of `every mailbox` (verified live 2026-10-21: one event, about 50 ms for 13 Exchange mailboxes), never a loop over the mailboxes. The account's Trash and Junk are found with `accountSpecialLookup` (by the owner's account id, as delete and spam find them, never by name) and left out by `is`; a mailbox named as `mailbox` is searched whatever it is. The script prints one section per mailbox with hits, joined by U+001C (`AppleMailClient.mailboxSeparator`), each the account name and Mail id, the mailbox path (`spwMailboxPaths`) and the `listEmailsScript` fields, so every mail id names the mailbox the mail lies in; `parseAllMailboxes` reads them with `parseListing`, and sorting, paging and `total` run over all of them in Swift. Gmail shows one mail in a folder per label (`INBOX`, `[Gmail]/All Mail`, a label folder), so `AppleMailClient.onePerMail` keeps one row per account and Message-ID: the one from `INBOX`, else from a folder outside `[Gmail]/`, else the first in Mail's order; `total`, and with it an unread or flagged count, then counts each mail once. The same applies to any account: copies of one mail in two folders of an account share the Message-ID and show once (a search of one `mailbox` is not folded). A list of unequal length across the mailboxes is `mailboxesChangedMarker`, a mailbox whose columns differ is `MailFailure.mailboxChanged` naming it. `search_body` needs `mailbox` (`MailError.missingField("mailbox")`; the TS handler refuses it first). Unverified live: that `is` excludes an account Trash that is Mail's top-level `trash mailbox` itself rather than its child, and the On My Mac part (`every message of every mailbox whose ...` at app level); `LiveMailTests` has a case.
- **`get_email` reads one mail with one script and returns every field Mail has for it** (SPEED-833, `MailReading.swift`): its `id`, `subject`, sender, `read`, `to`, `cc`, the date as ISO 8601 with the host offset (from `«class isot»`, like `list_emails`), `flag` (from `flag index of m`, named as in the listing), the plain-text body, `mailbox`/`account` from the mail id, and `attachments` (`index` = 1-based position in `mail attachments of m`, `name`, `size` when Mail knows it, `mime_type`). `include_headers`/`include_source` add `all headers of m`/`source of m`, cut inside the script at `MailReading.rawTextLimit` characters with `headers_truncated`/`source_truncated` (the TS `RAW_TEXT_LIMIT` that the tool description and schema quote is a manual alignment); the keys appear only when asked for. Fields leave the script joined by ASCII GS, list items by RS, attachment fields by US, and every free-text value goes through the script's `spwClean` handler, which strips those three characters and FS (the all-mailbox search's section separator), so a crafted subject, body or attachment name cannot forge a field. A message id no longer in its mailbox fails `messageLookup` with `mailNotFoundMarker`, reported as `MailFailure.mailNotFound` (`MAIL_NOT_FOUND`) naming the mailbox and account.
- **Mail rules are read-only, and that is a security boundary** (SPEED-841). `list_rules` (`MailRules.swift`, tool `listMailRules`) reads every rule with its conditions and actions (verified live: `rule type` and `qualifier` `as string` give names such as `from header` and `does contain value`); a condition's header is read as `«property rhed»`, because a bare `header of` does not compile against Mail's dictionary, which also has a `header` class; its script prints records separated by ASCII RS/US (`character id 30`/`31`), not `||` and newlines, because a rule's expression or reply text may contain either. Unverified live: that `primary email` is the address Mail would pick on its own (`LiveMailTests` compares the preview's `from` with the sender of the same message saved as a draft). `list_signatures` (`listMailSignatures`, read-only) returns the signature names, cleaned by `spwClean` and joined by RS. `send_email`, `reply_to_email` and `save_draft` take `signature`: every script of the call starts with `if not (exists signature ...) then error signatureNotFoundMarker` (`MailFailure.signatureNotFound`, `MAIL_SIGNATURE_NOT_FOUND`), including the unconfirmed send's one read-only sender script, and the sending script sets `message signature` before `send`/`save`; the preview and report carry `signature` only when one was chosen (Mail adds the signature's text, which the preview `body` does not show, so the skill tells Claude to name it to the user). Without `signature` the new-message and reply-send scripts set `message signature` to `missing value`, which `Mail.sdef` allows (type `signature` or `missing value`) and which ran live on a saved draft, so Mail cannot add the account's default signature unpreviewed. Whether Mail adds that default to a scripted message at all is reported both ways (not added, "broken since Tiger": https://www.macscripter.net/t/setting-the-signature-for-a-new-message-in-apple-mail/71752; added and then overwritten by the scripted content: https://www.macscripter.net/t/use-default-signature-in-new-mail-message/62300), hence the explicit clear. Forward and redirect never touch it, since any change to a forward empties it. No attachments: the host-side mcp-os cannot tell which project called it (SPEED-842). A turned-off account is refused before the message is made, by a send and a draft alike (`if not (enabled of spwAccount)`, `MailFailure.accountDisabled`, `MAIL_ACCOUNT_DISABLED`): live, Mail ignored a `sender` of a turned-off account, given before or after `make`, and filed the draft in the default account under the default address. Verified live (2026-10-20): `save` + `close saving yes` leaves exactly one draft, unsent, in the Drafts of the enabled account named, with its address as sender and the body's line breaks; the test Mac has one enabled account, so filing into a non-default account's Drafts is unverified. Unverified live: any `message signature` (the test Mail has no signature), on a new message, a windowless reply or after `content`.
- **The TS mail tools mirror the Swift split**: `mail-shared.ts` (time budget, `runMail`, `MAIL_FAILURE_TEACHING`, schema pieces several modules use), `mail-reading.ts` (clients, mailboxes, list, get, search), `mail-organizing.ts` (the batch tools and `createMailbox`), `mail-sending.ts` (send, reply, forward, redirect, drafts, signatures), `mail-rules.ts` (rules, check mail); `mail-tools.ts` only assembles them in `createMailTools`. A module exports only what another module imports (its tools and handlers); tests stay in `mail-tools.test.ts` and import the handlers from their module.
- **The mail tools reject undeclared arguments** (`withDeclaredParams` in `mail-tools.ts`), so a `client` argument fails with a teaching error instead of being dropped by `mail-cli`. A new parameter is declared in the same change that makes `mail-cli` read it.
- **`outputSchema` mirrors what `mail-cli` prints**, nesting included (`getEmail` returns `{ email: {...} }`), with `read` a boolean, `message_count`, `unread_count`, `attachment_count` and `total` numbers (`AppleMailClient.ListedMessage.json`/`parseMailboxes`); `mail-tools.test.ts` compares the key tree of each tool's schema with a sample of the CLI's output. A key added to a Swift result is declared in the schema and in that sample in the same change.

## Reminders (EventKit)

- **Public EventKit only.** `reminders-cli` talks to `EKEventStore` and nothing else: no AppleScript, no reading the Reminders SQLite store (needs Full Disk Access), no private ReminderKit. Consequence: flags, native tags, subtasks, sections, images and smart lists are out of reach; "tags" are `[#tag]` markers inside the notes field (`combineTags`/`extractTags`/`stripTags`), parsed back into a separate `tags` array.
- **Glossary** (tool params, schemas and docs use these words): _list_ = an `EKCalendar` that holds reminders (never "calendar"); _reminder_; _tag_ = a `[#tag]` marker; _due date_ is _all-day_ (`YYYY-MM-DD`, components without time fields) or _timed_, and always _floating_ (`timeZone == nil`: 9:00 stays 9:00 in every zone); _alarm_ (not alert/notification); _recurrence_ (not repeat); _completed_.
- **Due dates go through `dueDateComponents(from:timeZone:)`/`dueDateString(from:timeZone:)`** in `RemindersCLI.swift`; `timeZone` defaults to the host zone and exists so tests pin explicit zones (CI runners sit in UTC, where an offset conversion is indistinguishable from none). Input: `YYYY-MM-DD` (all-day), `YYYY-MM-DDTHH:MM:SS` (kept as typed, never resolved through the host zone, so a DST-gap time stays what the user asked for) or the same with an offset/`Z` (converted to host wall clock); anything else, including unpadded dates and impossible dates, is rejected. The components always carry the Gregorian calendar (EventKit raises otherwise, and `Calendar.current` need not be Gregorian) and no time zone. Output: `YYYY-MM-DD` or local time with an explicit UTC offset (`+00:00`, never `Z`, via SharedCLI `iso8601String(from:timeZone:)`), plus `all_day`; `completed_date` is local time with offset.
- **One date parser for both EventKit CLIs:** SharedCLI `parseISODateInput` classifies input as a bare day, a wall-clock time or an instant (strict, zero-padded, impossible dates rejected). Reminders map it to floating components (above); `calendar-cli` resolves it with `eventDate(from:timeZone:)`: a bare day is local midnight, a wall-clock time is local time, an instant is kept. Event output stays UTC with `Z`. `parseISO8601` accepts instants only: its old bare-date fallback turned `2026-06-15` into UTC midnight, which is the previous evening west of UTC, so never route a bare day through it.
- **`update_reminder` is a PATCH:** an omitted field keeps its value; JSON `null` on `due_date` clears the due date and drops the recurrence rules with it (EventKit refuses a recurring reminder without a due date). `notes` and `tags` share one EventKit field; `mergeNotes` replaces only the side the caller sent and keeps the other byte-for-byte (`tags: []` clears tags); `completed: false` reopens. A `list_id` that names several lists is refused (`CLIError.ambiguous`), never resolved to the first match; the same SharedCLI `resolveSingleCalendar` guards the target calendar of `create_event`. Listing (`list_reminders`, `list_events`) still merges every calendar a shared name matches.

## Transcription

- Fully local: raw audio and transcript passes never leave the machine (see security rules — this is a privacy invariant, not just a design choice).
- Models are auto-selected per pass from the runtime GPU class (`accel.rs`: Metal on macOS, Vulkan on Windows — ADR-085; CUDA deferred). No user model picker — do not add one. macOS asserts `GpuClass::Discrete` rather than probing; a Metal init failure falls back inside whisper.cpp (visible in logs via the routed whisper hooks).
- No speaker diarization — deliberately removed as inherently unreliable (ADR-075, which also removed sherpa-onnx and every Windows CRT workaround with it; see cross-platform rules). Do not reintroduce diarization or swap in another engine.
