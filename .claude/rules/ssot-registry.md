# SSOT Registry — edit the SSOT, never a call-site copy

Never hand-write a path/value/model-string where an SSOT exists; a wrong literal is fixed by calling the SSOT, not by correcting the string.

- `defaults.rs::ANTHROPIC_MODELS`: the static Anthropic model catalog, metadata only. It owns model names (`family`), pricing, the per-model `one_million_context` policy, `default_effort` and the per-model `effort_levels` the slider falls back to for the current model while no picker rows are held; the model-pin validator (`is_selectable_anthropic_model_id`) accepts its ids, and the `[1m]` form only for a model whose `one_million_context` is not `Never`. Frontend reads it via `list_anthropic_models` + `AnthropicModelsService`. It is never the source of a picker row (ADR-089, SPEED-663 amendment): not of which models an account is offered, not of a fallback list while the session has not reported its models, not of effort stops for a model Claude Code lists, of any context window, or of plan limits (next entry). Never hard-code model strings: ids are compared through `canonical_anthropic_model_id`, and the bare-or-`[1m]` wire id is chosen only by `anthropic_wire_model_id(catalog_id, plan)`.
- `desktop/src-tauri/src/control_channel.rs`: Claude Code's stream-json control channel on the live chat session, the source of truth for Anthropic sessions (ADR-089). `initialize` gives the account's model list, per-model effort stops and the plan (`model_picker.rs::build_picker` behind `list_model_picker` + `ModelPickerService`, whose `label()` is the one model-label function for the picker, the pill, message metadata and `/model` chips); `get_usage` gives the plan usage limits (`get_plan_usage` + `PlanUsageService`); `get_context_usage` gives used tokens, the window and the categories (`get_context_usage` + `ClaudeControlService`). The typed structs there are the only parsers of these payloads. Missing data is hidden, never a fabricated 0% or 200k; proxy-routed providers send none of these queries; besides `interrupt` on Stop, their only control requests are `set_model`, which every model switch on a live session uses (ADR-088, SPEED-696), and `apply_flag_settings`, which every effort change on a live session uses (SPEED-707).
- `desktop/src-tauri/src/history.rs::CostState`: the only parser of the `cost-state` transcript line Claude Code writes at exit (and on `/clear`), from which the resume snapshot starts (`compute_resume_snapshot_impl`). It mirrors, field by field, the schema the pinned binary restores from; the snapshot takes the cost, the tokens and the dominant model from the typed struct of the last line that schema accepts, as Claude Code does, and never re-reads those fields from the raw JSON. The resume captures are version-pinned (`the_resume_captures_are_of_the_pinned_claude_code`); the schema itself is re-checked by hand at every bump (architecture rules).
- `defaults.rs::EFFORT_LEVELS`: the Claude Code effort levels Speedwave can pin (`low` … `max`, slider order). Everything else derives from it, never a second list: pin and live-pick validation (`pin_cmd::validate_effort_level`), the catalog's per-model level lists, and the composer's slider order for every provider kind (`ActiveProviderSummary.effort_levels`), which is also the full stop list of a routed provider.
- `crates/speedwave-version`: the SSOT for the app version. Tracked version fields (every `Cargo.toml` in the repo: the three app crates plus `crates/pii-engine`, `crates/pii-engine-wasm`, `crates/pii-ner` and `containers/proxy`, which carry no app version at all and are pinned at `0.0.0` only so no Cargo.toml in the repo shows anything else, plus `package.json`/`package-lock.json` files, `tauri.conf.json`, the five native CLI `Info.plist`) hold the literal `0.0.0` and nothing reads them: Rust reads `env!("SPEEDWAVE_VERSION")` (below), Tauri gets its version via `--config` at build time, the native plists are stamped in a build-dir copy by `scripts/build-native-macos.sh`, MCP workers hardcode their version in code, and nothing is published to npm. The real version comes from git at build time: `build.rs` in `crates/speedwave-runtime`, `crates/speedwave-cli` and `desktop/src-tauri` all call the one shared helper, `speedwave_version::emit_cargo_version` (env override, else computed from git, else `0.0.0` with a `cargo:warning`; also emits `cargo:rerun-if-changed` for the git HEAD and refs, resolved via `git rev-parse --git-dir`/`--git-common-dir` so a worktree's build reruns on its own HEAD and on the shared common dir's refs), and every runtime call site reads `env!("SPEEDWAVE_VERSION")` instead of `env!("CARGO_PKG_VERSION")`. Tauri's own version is set per build via `--config`, never by editing `tauri.conf.json`; the MSI `bundle.windows.wix.version` field is left to tauri-bundler's own conversion from that version string, which already fails when the build/patch number exceeds 65535. Never hand-compute a version string or re-derive `N`/`Z` at a call site — call the crate's `speedwave-version` bin (`version`/`notes-range`/`validate-promotion` subcommands, clap-derived, gated behind the optional `cli` feature so the three build-dependency callers above never compile clap; every `cargo run -p speedwave-version --bin speedwave-version` caller passes `--features cli`) or its lib functions. The crate is split by responsibility (`error.rs`, `git.rs`, `release_line.rs`, `version.rs`, `notes.rs`, `build_script.rs`, plus a `#[cfg(test)]` `test_support` module for shared fixtures); `lib.rs` carries only `mod` declarations and `pub use` re-exports.
- `config.rs::ProjectUserEntry::effort_pin`: the only on-disk store of a chosen effort level, for every provider kind. **Desktop-only:** three Desktop paths use it.
  - `chat.rs::launch_effort_level` carries it to Claude Code as `--effort <pin>` at every chat spawn.
  - A composer pick reaches a live session as an `apply_flag_settings` control request, which writes no settings file and stores no level (SPEED-707; the pinned 2.1.295, like 2.1.282, records nothing in `.claude.json`, and 2.1.267 recorded only the launch-hold release flags `unpin…LaunchEffort: true`).
  - `pin_cmd::ensure_effort_pin_migrated_in` removes the container's `settings.json` `effortLevel` on every run, so that key is never a second store; the bundled template must not seed it back (SPEED-664).

  `crates/speedwave-cli` reaches none of these (it depends only on `speedwave-runtime`), so a CLI spawn ignores the pin and leaves the key alone. Do not state the rule unqualified, and move the spawn flag and the migration into `speedwave-runtime` before claiming the CLI honours it.

- `claude_settings.rs` (`get_model_pin`/`set_model_pin`/`clear_model_pin`/`restore_model_pin`/`normalize_model_pin`): the only on-disk store of the project default Anthropic model for new chat tabs is the container's own `settings.json` `model` key (ADR-092); there is no `config.json` field and no migration. `chat.rs::launch_model_id` resolves the spawn's `--model` (tab override, else the pin when `chat::validate_launch_model` accepts it, else the alias `default`). A composer pick is tab-scoped AND writes this store: on a live session it goes to that tab's process as a `set_model` control request (`switch_chat_model`), and unless Claude Code refuses it, becomes the tab override and writes the pin (`pin_cmd::set_model_pin`, or `clear_model_pin` for the `default` alias). A typed `/model <id>` writes the pin through `restore_model_pin` first and becomes the tab override only when that write succeeds. `config.json`'s LLM entries store no Anthropic model: the self-heal and every `update_llm_config` save clear it (`LlmConfig::clear_anthropic_models`). Before clearing, the self-heal moves a model that config written by 0.18 and earlier still holds straight into the `settings.json` `model` key (`config.rs::carry_anthropic_model_to_pin` through `claude_settings::set_model_pin`, ADR-088 decision 7 amendment).
- `defaults.rs::CLAUDE_CODE_MODEL_ALIASES` — Claude Code's built-in `--model` aliases (`default`/`best`/`fable`/`sonnet`/`opus`/`haiku`/`opusplan`); `containers/entrypoint.sh`'s settings.json foreign-model guard mirrors this list, never a hand-written alternation.
- `defaults.rs::CLAUDE_VERSION` — the Claude Code version pin (concrete semver, never `latest`).
- `defaults.rs::BUNDLED_PLUGINS` / `BUNDLED_PLUGIN_MARKETPLACE` — the official Anthropic plugins installed+enabled at container start, rendered into the claude service env by `compose/mod.rs`; never hand-list the plugin set elsewhere.
- `resources.rs` — every container mem/CPU/tmpfs/shm number + Lima VM sizing (`host/2` clamped; macOS-only — WSL2 memory is deliberately unmanaged). Always-on containers: the Claude ceiling is the formula `claude_memory_gib(vm_gib)` (base 6 GiB + 3 GiB per extra tab up to `MAX_CHAT_TABS`, clamped to `vm_gib - 2` GiB headroom, never below base; ADR-091), threaded into the renderer as `claude_resources(resolved_vm_memory_gib())` — the Windows 16 GiB RAM-detection fallback keeps Windows at the 6 GiB base; `HUB_RESOURCES` / `PROXY_RESOURCES` stay consts; per-worker limits on `consts::McpServiceDescriptor.resources`; plugin envelope in `consts.rs` (`PLUGIN_*`). `MAX_CHAT_TABS` is also the tab-capacity SSOT: the desktop registry cap imports it and the TS mirror in `chat-session-store.ts` is cross-read-tested (`max_chat_tabs_matches_ts_mirror`). Limits are ceilings, not reservations — overcommit is OK. Minimum supported host: `MIN_SUPPORTED_HOST_GIB` (16 GiB) — never design or size features for smaller hosts.
- `transcription/model_catalog.rs` — Whisper model catalog (files, pinned URLs, SHA256, display names; frontend via `list_transcription_models`; the recordings screen names no model, it compares `TranscriptSummary.finalize_model` with the high-quality model's key) plus the pinned Silero VAD model (`VAD_MODEL`) and the pinned speaker-diarization model (`DIARIZATION_MODEL`, ADR-098; frontend via `RecommendedModelAck.diarization`); the live and offline-pass models are auto-selected from the probed runtime GPU class (`accel.rs::live_model_for_this_build`/`finalize_model_for_this_build`, ADR-085). Bumping a model = editing one const.
- `usage.rs` + `usage_cost.rs` — final tokens + cost for the dashboard (`get_llm_usage`), chat footer (`get_usage_for_response`/`get_conversation_cost`), and the in-container statusline. Proxy usage JSONL + host-side cost sidecar keyed by `response_id`. Cost enrichment never rewrites the usage JSONL; unpriced stays `null`, never `0.0`; never sum Claude Code's `total_cost_usd` with proxy cost. Full invariants: local-llm rules.
- `log_ts.rs::log_timestamp()` / mcp-shared `ts()` — the one log timestamp format (RFC 3339, millis, local offset with colon). Never `toISOString()` for a log-line prefix.
- `diagnostic_sources.rs::DIAGNOSTIC_SOURCES` — every diagnostic file shown in the /logs UI and packed into the diagnostics ZIP. New log file = new registry entry (non-`displayable` = ZIP-only), never a hand-wired path.
- `engine_path.rs` — all host→engine path handling (`to_engine_path`/`str_to_engine_path`/`vm_path_join`, `strip_extended_length_prefix`).
- `compose/networks.rs` — compose network names: `project_network_name` (the main `<prefix>_<project>_network`), `egress_less_network_name`/`egress_less_network_names`/`egress_less_network_owners` (one per `egress_less` descriptor, the last paired with the compose service it isolates), `is_egress_less_network` (office, `_custom`, `_cx_<n>`) and `is_builtin_egress_less_network` (office only), the Custom MCP bridges (`custom_host_network_name`, `custom_egress_network_name`), `effective_network_name` (the name compose gives a network key), and `legacy_compose_network_name` (the `<project>_<key>` name compose gave a network declared without `name:`, which the start looks for to retire). The renderer, the integrations filter, `SecurityCheck`, the pre-create in `LockedRuntime` and unregister all derive names from here; never format a network name at a call site.
- `compose/addressing.rs` — `host_bind_address()`/`host_gateway_ip()`: every host TCP listener bind and every container→host gateway IP. `mirror_relay_port(bind)` (ADR-080) is the deterministic container-facing relay port under WSL2 mirrored mode; the compose URL injectors and container-facing lock naming call its exported wrapper `container_facing_port(bind)` (relay port, or unchanged off-mirrored) — one SSOT shared with the guest `socat` relay supervisor.
- `compose/workers.rs::worker_gateway_url` + `worker_os_url_state`: the container-facing URL of a host-side worker (through `container_facing_port`) and the one verdict on whether the hub's rendered `WORKER_OS_URL` still targets the live mcp-os port (exact URL match: `RenderedUrlState::{Absent,Current,Stale}`, shared with `compose/pii_ner.rs::ner_url_state`; an unparsable compose is `Stale`). Desktop's `reconcile_compose_port` consumes that verdict; never rebuild the URL or probe the compose text for a port at a call site (a substring probe matched `:80` inside `:8080` and suppressed the reconcile).
- `runtime/mod.rs::project_has_compose_file(project)` — the one probe for "has this project's compose.yml been rendered". A configured-but-never-initialized project fatally errors per-project `compose_ps` — guard with this helper (or degrade gracefully on `Err`), never a hand-rolled `Path::exists()` on a compose path.
- `url_validation.rs` — the shared SSRF validator (+ `PrivatePolicy`); Desktop re-exports it. One validator — never a second regex or copied constants.
- `crates/ip-policy::is_private_or_reserved` — the one private/reserved IP predicate (loopback, RFC 1918, CGNAT, link-local, TEST-NETs, RFC 2544, IPv6 ULA/link-local/site-local/documentation/discard). Std-only so the standalone proxy workspace can path-depend on it; `url_validation.rs` re-exports it (`pub use`), so runtime and Desktop callers keep their import path. It refuses Teredo `2001::/32` and local-use NAT64 `64:ff9b:1::/48` outright but does not unwrap an IPv6 address that carries an IPv4 one: `ip_policy::embedded_ipv4` is the one decoder (IPv4-mapped, IPv4-compatible, well-known NAT64, 6to4), and each caller applies the predicate to the decoded address too (`url_validation.rs::host_block_reason`, `spw-egress` `resolve.rs::is_forbidden_target`). Never copy its ranges into a second predicate.
- `build.rs::IMAGES` + `ImageDef.hash_inputs` — image catalog and what rebuilds each image. Full rules: images-builds rules.
- `pastes.rs::open_pastes_dir` over `pinned_dir.rs::PinnedDir`: the only way host code opens the project's pastes directory, which the claude container can rewrite (ADR-094 decision 9). Every create, rename and removal there goes through the returned `PinnedDir` (Unix: names resolved against the held directory with `O_NOFOLLOW`; Windows: the components held open without `FILE_SHARE_DELETE`), never `create_dir_all` followed by a path-based write.
- `custom_mcp::effective::resolve_effective` (via `resolve_for_project`) — which Custom MCP servers run; carried on `ResolvedIntegrationsConfig::custom_mcp` for the renderer, `enabled_images` and `enabled_hub_service_ids`, and recomputed by `custom_mcp::expectations_for` for every SecurityCheck gate. An unreadable MDM file resolves through `effective::unreadable_managed_policy` (Custom MCP off). Never filter Custom MCP entries at a call site.
- `custom_mcp::build::image_tag_for` — the only Custom MCP server image tag; the Desktop records `image_tag_for_dir` (over the review's staging dir) at approval.
- `compose/custom_mcp.rs` — Custom MCP service names (`Role::service_name`), labels (`ROLE_LABEL`, `ID_LABEL`, `CONSENT_LABEL`), the egress URL and the upstream URL; `security_check/custom.rs` reads them from there. Limits: `resources::CUSTOM_MCP_{GUARD,SERVER,EGRESS}_RESOURCES`.
- `fs_perms.rs` — owner-only permissions (Unix chmod ↔ Windows DACL) and durable fsync-before-rename writes. `binary.rs` — the only module that constructs process spawns: `system_command` (non-interactive system tools; CREATE_NO_WINDOW + WSL_UTF8), `run_powershell` (deadline-bounded), `command` (bundled binaries), `interactive_command` (TTY-visible spawns). The deadline-bounded capturing helpers (`run_with_timeout_capture`, `wait_with_output_timeout` and `runtime::vm_exec_run`, all through `wait_for_piped_child`, plus the default `CommandRunner::run_with_timeout`) read output on threads (`read_on_thread`) and, once the child exits, await it for at most `consts::PIPE_DRAIN_GRACE` (`exited_child_output`): a process the child left behind, such as the `ssh` of a killed `limactl shell`, can hold a pipe open indefinitely. `RealRunner::run` and plain `.output()` still wait for every pipe to close. Raw `Command::new` outside `binary.rs` is drift-tested (`tests/no_raw_command_spawn.rs`, escape hatch `// SSOT-allow: <reason>`).
- `consts.rs::SLACK_OAUTH_BASE_SCOPES` / `SLACK_FEATURES`: the Slack user scopes. Base scopes are required and are the only ones `integrations_cmd.rs::required_scopes_for("slack")` checks for the re-authorise banner; each `SlackFeature` (id, label, scopes) is opt-in from the Slack card, and `slack_features.rs::requested_scopes` builds the sign-in request from base scopes, the features the stored grant already has and the one being enabled. A new capability that needs a scope is a new `SlackFeature`, never a new entry in the base list (ADR-071 point 12).
- `config.rs::ProjectUserEntry::custom_mcp` — the only store of Custom MCP servers and their consent (user config only; `ProjectRepoConfig` never gains the key, test `repo_speedwave_json_cannot_set_custom_mcp`). `custom_mcp/model.rs::CustomMcpEntry::validate` is the one validator of an entry (name `^[a-z][a-z0-9-]{0,30}$` without a trailing or doubled `-` or the `-up`/`-egress` suffixes; npm name; exact semver; host port and path); `custom_mcp/effective.rs::resolve_effective` the one decision which servers run (approval, beta, MDM, `CUSTOM_MCP_MAX_PER_PROJECT` in name order) with a reason for each excluded one; `custom_mcp/paths.rs` the one builder of `<data_dir>/custom-mcp/<project>/<name>/{guard,egress,build}` and of the relay's `relay-<name>/` (`relay_dir_in`, `relay_dir_name`, `server_of_relay_dir`; every level owner-only, symlinks refused); `custom_mcp/policy.rs::write_guard_policy`/`write_egress_config` the only writers of the guard `policy.json` and the egress `egress.json` (atomic, 0o600, validated against what the guard accepts); `consent_digest` the one consent digest, computed only in Rust (UI never computes it) over the source (every lock field, env key names sorted; a host server's port and path), `workspace_mode` and `pii_mode`, never over tool decisions, domains, `enabled` or `approved_at`.
- `consts.rs` — ports, names, literals: `HOST_GATEWAY_ALIAS`, `MIRROR_RELAY_GATEWAY_IP` (ADR-080), `DATA_DIR`, WSL distro name derivation, nerdctl pin, OAuth constants, `RESERVED_ENV_KEYS`, service descriptors (`TOGGLEABLE_MCP_SERVICES`/`TOGGLEABLE_OS_SERVICES`, `BUILT_IN_SERVICE_IDS`), MDM/managed-settings path literals (`MANAGED_CONFIG_VENDOR_DIR`, `MANAGED_CONFIG_FILE`, `CLAUDE_MANAGED_SUBDIR`, `MANAGED_SETTINGS_FILE`), Custom MCP literals (`CUSTOM_MCP_SERVICE_PREFIX`, the `custom-` namespace no plugin slug or `service_id` may use; `CUSTOM_MCP_MAX_MIN_RELEASE_AGE_DAYS`, the upper bound of the managed `custom_mcp.min_release_age_days`; `CUSTOM_MCP_DEFAULT_MIN_RELEASE_AGE_DAYS`; `CUSTOM_MCP_MAX_PER_PROJECT`; `CUSTOM_MCP_STATE_DIR`; `CUSTOM_MCP_FORBIDDEN_ENV_KEYS`/`_PREFIXES`, the env names a server's user-supplied env may not set on top of `RESERVED_ENV_KEYS`; `CUSTOM_MCP_GUARD_POLICY_FILE`/`CUSTOM_MCP_EGRESS_CONFIG_FILE`; `CUSTOM_MCP_RESOLVER_IMAGE`, `CUSTOM_MCP_NPM_REGISTRY` and `CUSTOM_MCP_RESOLVE_TIMEOUT` for the npm resolver, whose envelope is `resources.rs::CUSTOM_MCP_RESOLVER_RESOURCES`). In-VM nerdctl name-store coordinates: `NERDCTL_DATA_ROOT` (`/var/lib/nerdctl`), `CONTAINERD_ADDRESS` (`/run/containerd/containerd.sock`), `CONTAINERD_NAMESPACE` (`default`), `nerdctl_addr_hash()` (parameterless — hashes `CONTAINERD_ADDRESS` internally, `sha256(address)[0..8]` matching nerdctl's `getAddrHash`); `runtime/mod.rs::NameStoreLayout::store_dir`/`name_store_script_header` read all four directly rather than threading an address/namespace pair through the struct.
- Custom MCP relay layout: `consts.rs::CUSTOM_MCP_STATE_DIR`, `CUSTOM_RELAY_BRIDGE_NAME`, `CUSTOM_RELAY_LOCK_DIR`, `CUSTOM_RELAY_LOCK_EXT`, `CUSTOM_RELAY_SERVER_DIR_PREFIX`, `CUSTOM_RELAY_ENDPOINT_FILE`, `CUSTOM_RELAY_TOKEN_FILE`, `CUSTOM_RELAY_PORT_FILE`; every `relay-<name>` path and the relay lock dir (`paths::relay_lock_dir_in`, the Desktop writer and the CLI reader `custom_mcp/relay.rs` alike) come from `custom_mcp/paths.rs` (the renderer, the SecurityCheck and the relay alike, the renderer creating the directory before a host guard mounts it); the endpoint URL is built only from `compose::container_facing_port` and `HOST_GATEWAY_ALIAS` (`custom_host_relay.rs`), the upstream address only from `http_forward.rs::HOST_LOCAL_UPSTREAM_IP`, the unavailable body only from `http_forward.rs::HOST_APP_UNAVAILABLE_BODY`.
- `telemetry_env.rs` — the one telemetry-field↔`OTEL_*` env-key table (`TelemetryField` + `env_key_for` + `ENABLE_KEY`), read by both `resolve_telemetry`'s `locked_keys` logic and the env map. Never hand-write an `OTEL_*` key at a call-site; a drift test guards the two readers.
- `config.rs::resolve_telemetry` — the single telemetry merge (defaults → user → MDM per-field, presence-is-lock, master-switch lock, endpoint/header validation, kill-switch). Both the compose renderer and the Tauri command read it, so the UI shows exactly what reaches the container.
- `mcp-servers/policies/rules.yaml`: the built-in PII rule library (7 rules: id/displayName/patterns/validator, no flags) — the one source of truth for what a rule id detects. Both `crates/pii-engine::policy.rs` (engine fallback) and `crates/speedwave-runtime::pii_policy.rs` (resolver) embed it independently via `include_str!`; never hand-duplicate a rule's regex at a call site, edit `rules.yaml` instead.
- `mcp-servers/policies/templates/*.yaml`: the PII policy template presets (`strict`/`gdpr-art32`/`eu-ai-act-art5`), v3 schema (`categories` keyed by `rules.yaml` rule id, plus optional additive `rules`/`keywords`). Not code: only Rust `pii_policy.rs` reads them, via `include_str!` (the pre-WASM TS `template-loader.ts` reader is gone, ADR-083). Never hand-list a template's category mapping in Rust, edit the YAML instead.
- `crates/pii-engine` token format + `TOKEN_SPAN_RE` (`scan.rs`, `pub const`): the one PII token span shape, `[CATEGORY:TOKEN_<base64url(AES-SIV ciphertext)>]`, and the one regex that recognizes it. Never hand-write the token format at a call site; both the native proxy and the WASM-wrapped hub scan/detokenize through this regex (ADR-083). The hub's only TS copy, `hub/src/token-spans.ts`, counts spans for the `tool-args` audit and is alignment-tested against `scan.rs`.
- `runtime/oneshot.rs::OneshotSpec` + `ContainerRuntime::run_oneshot` (public `LockedRuntime::run_oneshot`, no compose lock, refused during engine teardown): the only way to run a throwaway container. The hardening is not a knob: every run is `--rm --read-only --cap-drop ALL --security-opt no-new-privileges --user <CONTAINER_USER_UNPRIVILEGED>` with `--memory`/`--cpus` and a `noexec` `/tmp` tmpfs from a `resources.rs` envelope, bounded by the spec's deadline through `CommandRunner::run_bounded` and force-removed by name when the run fails or times out (`run_and_reap`). Spec strings may not carry `$` or control characters (the WSL transport re-parses the line), mount sources go through `engine_path::to_engine_path`. `custom_mcp/npm_resolve.rs::resolve_npm_lock` is its first caller: it validates the npm name, exact version and MDM scopes first, wipes and restages the review's own `custom-mcp/<project>/<name>/previews/<id>/` (`promote_preview` moves it to `<name>/build/` on approval) with a generated `package.json` and `resolver_npmrc()` (only `CUSTOM_MCP_NPM_REGISTRY`, scripts off) (the repository's lockfile and `.npmrc` are never read), runs `npm install --package-lock-only --ignore-scripts --before=<now − min_release_age_days, default CUSTOM_MCP_DEFAULT_MIN_RELEASE_AGE_DAYS>` in `consts::CUSTOM_MCP_RESOLVER_IMAGE` on the default bridge (full internet, accepted deviation), and refuses a lockfile that is not v3, lacks the package's sha512 integrity or marks any package `hasInstallScript`.
- `pii_policy.rs::ResolvedPiiPolicy::services`: the per-service hub settings in `policy.json` (`services.<id>.pii_mode`, one explicit entry per running Custom MCP server, filled by `config.rs` from `custom_mcp::effective::resolve_effective`). It is part of the written file, so `POLICY_DIGEST` covers it and a PII mode change recreates the hub; omitted when empty.
- `crates/pii-engine::default_policy_json()`: the compiled-in default `policy.json` v3 (every `rules.yaml` rule tokenize-on, no keywords). SSOT for "no `POLICY_FILE`" fallback: the WASM binding delegates to it (`mcp-servers/policies/src/engine.ts`) and the proxy calls it natively (`containers/proxy/src/pii.rs::default_state`); both callers are on the v3 API.
- `crates/speedwave-runtime/src/pii_key.rs` (`project_key_path_in`/`read_project_key_in`/`ensure_project_key_in`): the per-project PII tokenization key, 32 bytes, 64-hex, `<data_dir>/policies/<project>/key`, exclusive-create on first use. Never hand-build the key path or re-derive a key elsewhere; proxy, hub, and Desktop's display-side detokenization all read this one file.
- `containers/proxy/src/audit.rs` + hub `mcp-servers/hub/src/audit-pii.ts`: the PII detection audit filenames (`consts::AUDIT_PROXY_FILE`/`AUDIT_HUB_FILE`, `audit-{proxy,hub}.jsonl` under `<data_dir>/audit/<project>/`). One JSONL line per `(layer, category, action[, tool], count)`; never a scanned value. Registered in `DIAGNOSTIC_SOURCES` (`diagnostic_sources.rs`).
- `crates/pii-ner/tools/pins.json`: the pinned Redact model files (Hugging Face repo, revision, sha256 per file) the converter downloads and verifies; the Rust loader mirrors the source hash in `artifact/mod.rs::SOURCE_TFLITE_SHA256` (guarded by a test reading `pins.json`). Bumping the model = editing `pins.json`, rerunning `make prepare-pii-ner-model`, regenerating `crates/pii-ner/tests/fixtures/` with `tools/gen_fixtures.py` and updating the Rust hash.
- `desktop/src-tauri/pii-ner/manifest.json` (generated, gitignored): the one description of the converted model (shape, labels, pipeline defaults, file hashes); Rust reads shape and labels from it, never from constants.
- `compose/pii_ner.rs`: `live_service_in` (the one reader of `pii-ner.lock.json` for rendering), `ner_url_state` (the one verdict on whether `proxy.json` `ner.url` matches the live detector; Desktop's `reconcile_compose_port` consumes it), `validate_ner_url`, `DEFAULT_NER_LABELS` and `DEFAULT_NER_MIN_CONFIDENCE`; the proxy's `ner.rs` keeps a hand-mirrored copy of the URL rule (manual alignment).
- `consts::PII_NER_LOCK_FILE` / `PII_NER_AUTH_TOKEN_FILE` / `PII_NER_AUTH_HEADER`: the detector's lock, persistent token and auth header names; the header is cross-read against `containers/proxy/src/ner.rs::NER_AUTH_HEADER`.
