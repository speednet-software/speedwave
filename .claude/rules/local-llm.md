# LLM Provider Rules

Every session routes through the per-project Rust forwarder `proxy` (port 4000, compose network only), which relays native Anthropic `/v1/messages` with no translation. `llm.proxy_enabled` defaults to `true` (`unwrap_or(true)`), so the proxy is the primary Anthropic path for nearly everyone — the legacy direct-injection path is the fallback, scheduled for removal; do not build on it.

## Invariants (non-negotiable)

1. **The proxy container never holds a canonical Anthropic credential.** No `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` env name may reach it — the passthrough leg forwards the client's subscription OAuth header verbatim. Provider keys are injected exclusively as `SPW_KEY_<PROVIDER_ID>` by compose and read from `/tokens`. Guarded by the renderer's no-key-values/no-canonical-names test and the forwarder's `forward.rs` header tests — keep both green.
2. **OAuth sessions carry no auth env.** Injecting `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY`/`apiKeyHelper` into the claude container disables Claude Code OAuth. The `anthropic_oauth` branch injects `ANTHROPIC_BASE_URL` (passthrough) and model defaults only.
3. **Key VALUES never land in config.json or the rendered proxy.json.** Values live in `tokens/<project>/llm/<provider_id>_api_key` (0600, atomic, `Bearer `-stripped, CRLF-rejected); configs carry presence flags and `SPW_KEY_<ID>` env-name references only. Provider ids are plugin-grade slugs (`plugin::is_valid_slug`, never a second regex).
4. **`provider`, `base_url`, `providers`, `active`, `proxy_enabled` are user-only config.** Repo `.speedwave.json` may set `model` only — `merge_llm_repo()` strips the rest. A malicious cloned repo must not redirect traffic, add providers, or flip the kill-switch.
5. **Anthropic model strings have one static SSOT**: `defaults.rs::ANTHROPIC_MODELS` (names, pricing, legacy rows, the `one_million_context` policy, the fallback list), read by the frontend via `list_anthropic_models`. Which models an Anthropic account is offered comes from Claude Code's `initialize` control response on the live chat session (`model_picker.rs`, ADR-089), and the bare-or-`[1m]` wire id only from `defaults.rs::anthropic_wire_model_id`. No hard-coded model strings.
6. **Usage has one source of truth for final values.** The forwarder's per-request JSONL line plus the host-side cost sidecar (`cost-cache.jsonl`, keyed by `response_id`) are the SSOT for final tokens + cost (dashboard, chat footer, and the in-container `statusline.sh`, which reads the sidecar's `response_id`/`cost_usd` fields directly with last-write-wins dedup — the `speedwave` CLI binary has no usage command). The Claude Code result stream is a live preview reconciled to proxy values. Context usage and plan limits, which the proxy cannot see, come from Claude Code's control channel for Anthropic sessions (`get_context_usage` and `get_usage` on the live chat process, ADR-089; `get_usage` is experimental, so any failure means "no data" and the UI hides it). The result stream's `modelUsage[model].contextWindow` is the context-window fallback there and the live context source for proxy-routed providers, which send no control request. `rate_limit_event` is a status signal, never a meter. Cost enrichment never rewrites the usage JSONL; unpriced (subscription/unknown) stays `null`, never `0.0`. The `CostSource` enum (`usage_cost.rs`, wire strings `catalog`/`subscription`/`free`/`actual`/`unknown`/`deferred`/`failed`) is a two-consumer contract Rust ↔ TS `models/llm.ts::CostSourceKind` (test `cost_source_ts_union_matches_rust`) — never reorder/rename; `deferred` is the only non-terminal source (OpenRouter async cost) and drives the footer re-reconcile.
7. **A routed request through the proxy never carries a mid-conversation system turn upstream.** Claude Code gives every model id outside its catalog the `mid_conv_system` capability, so it puts `{role:"system"}` turns (the per-turn reminders, `tool_addition` blocks) inside `messages`. A strict chat template rejects them: llama.cpp with Qwen's GGUF template answers 500, and Claude Code retries until the turn fails. The forwarder answers such a request on a non-Anthropic route with 400 `capability_rejected: mid_conv_system` (`forward.rs::MID_CONV_SYSTEM_REJECTION`, Claude Code's gateway contract) before the PII scan and without calling the upstream. Claude Code then resends the same turn with the reminders inline, and keeps doing so until `/clear` or `/compact`. The Anthropic route forwards such turns unchanged. The direct path (a Local provider with custom headers, or `proxy_enabled=false`, see `apply_llm_config_in`) bypasses the proxy and has no such guard, so a strict template still answers 500 there; it is the fallback scheduled for removal, not a place to add a second copy of the guard. Do not replace this with `CLAUDE_CODE_MODEL_CAPABILITIES`: the public Claude Code build ignores that variable (checked on 2.1.267 and 2.1.282). The per-model `ANTHROPIC_DEFAULT_*_MODEL_SUPPORTED_CAPABILITIES` variables only match the exact configured id, so a `/model` switch to another routed model slips past them. Test-guarded in `containers/proxy/src/main.rs` and `forward.rs`.

## Env-var injection (compose/llm.rs)

- **Anthropic kinds inject no model env at all** (SPEED-541: the prior `ANTHROPIC_DEFAULT_MODEL` injection was dead code). The project config never carries an Anthropic model: the config self-heal and every `update_llm_config` save clear it from every Anthropic entry, the Anthropic active pointer and the v1 flat field (`LlmConfig::clear_anthropic_models`). Claude Code resolves the account default; the persistent `/model` pick lives in the in-container `settings.json` `model` key, written by the Desktop (SPEED-539, ADR-088 amendment). A config written by 0.18 and earlier still holds the model those versions ran as `ANTHROPIC_MODEL`, and the self-heal moves it into that pin (`config.rs::carry_anthropic_model_to_pin`, ADR-088 decision 7 amendment). It carries the active Anthropic entry's model, or, only when the active entry is not Anthropic, the model an inactive Anthropic entry kept. It saves the cleared config first and writes the pin after, so a failed config save leaves nothing to carry over a later pick. It overwrites an older pin. A pin write that fails (an id the pin rejects, a malformed `settings.json`) is logged as an error naming the model. Test-guarded: `assert_model_not_forced` in `compose/mod.rs`, extended to also reject `ANTHROPIC_DEFAULT_MODEL=`.
- **Speedwave never sets `CLAUDE_CODE_EFFORT_LEVEL`.** Per `env-vars.md`, it "Takes precedence over `--effort`, `/effort`, and the `modelSettings` and `effortLevel` settings" — setting it in compose would outrank the composer's live pick (`apply_flag_settings`, measured on the pinned binary), the user's `/effort` and the `--effort` launch flag, and compose bakes env in at container create (no way to change it without recreating the container). Test-guarded: `test_claude_env_has_no_effort_level` plus `assert_no_effort_level_forced` in `compose/mod.rs`, covering the Anthropic proxy path, the Anthropic direct path, and routed local/OpenRouter.
- **Non-Anthropic kinds force `ANTHROPIC_MODEL=<provider_id>/<model>`**, `ANTHROPIC_CUSTOM_MODEL_OPTION` supplementary; the routed id must match the route prefix in the rendered proxy.json and must beat any persisted pick. `entrypoint.sh` drops a non-Claude model id from `settings.json` (anything but `claude-*` or a bare Claude Code alias such as `opus` or `fable[1m]`, so a slash-free local tag like `llama3.3` goes too) only when `ANTHROPIC_MODEL` is unset; a persisted pick that merely differs from a forced `ANTHROPIC_MODEL` is left alone (the env pin wins at startup). Its template merge rewrites the file only when the merge changes it, so a host-side pin write (`claude_settings.rs`, whose lock the container cannot take) is not lost to an unconditional rewrite.
- **Non-Anthropic kinds remap built-in aliases:** `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` all point at the routed `<provider_id>/<model>` so `/model opus|sonnet|haiku|fable` hits the wildcard route instead of 404ing on a bare `claude-*`. `ANTHROPIC_DEFAULT_HAIKU_MODEL` (subagent/background traffic) replaces the deprecated `ANTHROPIC_SMALL_FAST_MODEL`.
- **Anthropic kinds pin `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` only**, each alias to its latest catalog model, with the `[1m]` suffix only where every plan includes the model's 1M window (`one_million_context: EveryPlan`), the bare id for a model without one, and no pin for a latest model whose window depends on the plan (test `a_plan_dependent_1m_window_is_never_pinned_to_an_alias`): OPUS and SONNET because Opus 4.7 and later and Sonnet 5 run with the 1M window on every plan, Pro included, and behind the proxy Claude Code budgets a bare id at 200k (without the pin the `opus` alias, which subagents with `model: opus` and `opusplan` resolve, and the `sonnet` alias drop to that budget; test `anthropic_default_models_env_pins_opus_and_sonnet_to_their_1m_windows`); HAIKU because it keeps the undated catalog id. Opus 4.6 is the only Opus whose 1M window depends on the plan (usage credits on Pro); the composer picks its window per plan. FABLE is deliberately omitted (it resolves natively; test `anthropic_default_models_env_omits_fable_alias`). `[1m]` is real Claude Code model-id syntax — it must stay quoted in compose YAML (Go/nerdctl chokes on `[`); never strip it.
- **Provenance:** the routing model for non-Anthropic kinds comes from the active provider entry (`LlmConfig::effective_active_model`), never a foreign `active.model`. Anthropic entries never carry a stored model past the config self-heal, so no provenance check runs in the renderer for them.
- A `local` provider with custom headers falls back to the direct path — the proxy would consume headers addressed to the LLM server.
- **Windows mirrored-mode limitation (ADR-080):** host-side local LLM listeners (user-run Ollama/LM Studio/llama.cpp) are NOT relayed — `compose/llm.rs` emits `host.docker.internal:<raw port>` and no Speedwave process supervises those ports, so under WSL2 mirrored mode the proxy cannot reach them. Workarounds: switch WSL to NAT, run the LLM inside the distro, or hand-run a `socat` unit (see ADR-080 "Known limitations"). A supervised relay for configured provider ports is future work.
- **Local-only CLI flags (config.rs resolver, not compose):** an active `Local` kind adds `--exclude-dynamic-system-prompt-sections` (KV-cache prefix reuse) and `--append-system-prompt` with `prompts::local_llm_skills_nudge()` (static copy — never interpolate config values into it without a sanitizer; the v0.10-removed `local_llm_identity` shows the injection risk). Prompt **replacement** (`--system-prompt-file`) stays banned — removed in v0.10.0, do not reintroduce. Test-guarded (`resolve_injects_skills_nudge_*`, `resolve_never_replaces_prompt_*`).

## URLs, aliases, auth

- Discovery probe and save path share `validate_llm_base_url` (`llm_cmd/discovery.rs`, re-exported through `llm_cmd.rs` — the module was split into `llm_cmd/{discovery,usage}.rs`), parameterized by `PrivatePolicy`; render-side validation is `compose::validate_base_url` — never a third validator. The block list is fixed; changes require an ADR delta. The proxy URL (`http://proxy:4000`, routed by request-body model prefix, not URL path) is compose-internal and never flows through user-facing URL fields.
- `host.docker.internal` resolves inside containers (proxy carries `extra_hosts`) but not on the Desktop host — host-side probes call `http_util::rewrite_container_alias_to_loopback`. A saved loopback `base_url` is rewritten to the alias by `compose::canonicalize_local_base_url` (the persisted value must be reachable from inside the proxy container).
- A discovery probe with no key typed in the form falls back to the stored `local-llm` key and custom headers only for a local provider, read from the project the form names (`DiscoverLlmModelsArgs.project`, else the active project); the OpenRouter catalog probe never carries them (`discovery.rs::stored_credential`, used by the command and by the model auto-select probe alike), because they are the local server's credentials and openrouter.ai is a third party.
- `check_claude_auth` short-circuits via `project_needs_anthropic_auth`: only an active `anthropic_oauth` provider runs the in-container OAuth check; api-key/local/openrouter kinds and unconfigured projects skip it (routed to provider configuration, not an OAuth wall). Any new Anthropic-auth checkpoint uses the same predicate.

## When designing or fixing any feature, ask

- Does it talk to an LLM? It goes claude container → proxy — no host-side LLM calls except the discovery probe in `llm_cmd.rs`.
- Does it add a provider kind or change routing? Update the renderer (`compose/proxy.rs::render_proxy_config`), the injection (`compose/llm.rs`), the forwarder's routing/header logic, and the security-test expectations in the same change.
- Does it touch the forwarder's deps? Bump `containers/proxy/Cargo.toml` + its `Cargo.lock` together; build `--locked`.
- Does it surface usage numbers? Decide which source of truth (invariant 6) and document the choice.
- Local model context windows come from the discovery probe as `context_tokens: Option<u32>`; when `None`, propagate `null` — never substitute the 200K Anthropic baseline. `/v1/models` fields read, in order: llama.cpp `meta.n_ctx_train`, LM Studio `max_context_length`, LiteLLM `max_input_tokens` (OpenRouter rows carry `context_length`). A routed provider entry's `context_tokens` is written by a composer pick (`set_provider_model` stores the picked row's window, and clears it when the newly picked model's window is unknown), by the local model a Settings save auto-selects (`apply_model_auto_defaults`), and by a Settings save itself, which keeps the stored window while the entry's model is unchanged (`preserve_stored_entry_models`). It reaches Claude Code only as `CLAUDE_CODE_MAX_CONTEXT_TOKENS` at the next compose render, so a live-session wire `/model` pick runs on the previous window until the containers are recreated.
- Whether a project is Anthropic or routed is decided by the active provider's `kind`, never by the legacy `provider` field: `config::sync_llm_legacy_fields` writes `provider = "anthropic"` for an OpenRouter entry, so a `provider === 'anthropic'` test mistakes OpenRouter for Anthropic (it took the usage ring's default window away from every OpenRouter project without `context_tokens`). The legacy field is only a fallback while the active kind is unknown (config not loaded yet, just reset by a project switch, no `providers` list, or an active id missing from it); test mocks of `get_llm_config` and test fixtures of the chat state use the value that sync writes (`anthropic` next to kind `open_router`), never `openrouter`.
- Any new env injected into the `claude` service whose name contains `TOKEN`/`KEY`/`SECRET` (e.g. `CLAUDE_CODE_MAX_CONTEXT_TOKENS`) must be added to the `NoTokensClaude` allowlist in `compose/security_check.rs`, or the start gate rejects its own render and containers never start. Guard: `test_rendered_compose_with_routed_window_passes_security_check`.
